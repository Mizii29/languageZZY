**七个ZZY模块及完整菜单已经实现。** 任务增删改、完成、筛选搜索、排序、统计、TSV导出、JSON保存加载与撤销/重做均通过真实CLI测试；完整阶段回归证据在验收结束后记录。运行时仍为0.6.0a1，应用版本1.0，文件schema_version=1，三者分别标识。

## 功能与交互决定

程序采用逐行中文菜单，不解析Shell命令，不要求GUI或第三方包。菜单编号用text.safe_int转换；空行、未知编号、格式失败给可恢复提示。每次io.input先区分Null（EOF）与String，绝不对EOF调用trim/safe_int。提示立即显示，测试按固定stdin驱动真实CLI。

起始菜单固定为1新建、2打开、0退出。新建是用户明确选择，建立tasks=[]、next_id=1、无路径、无已保存快照的新会话；视为未保存，即使任务为空也不能冒充已有文件。打开必须完整校验成功才进入会话；读失败绝不自动创建空文件。

主菜单如下；每次显示任务数、next_id及未保存标记。

| 编号 | 功能 | 行为与阶段 |
|---|---|---|
| 1 | 列出任务 | 当前视图显示id/title/category/priority/done，空结果明确提示；P09-02 |
| 2 | 新增 | 输入标题、分类、优先级，确认后取高水位ID；P09-02 |
| 3 | 编辑 | 按ID定位，提交完整候选Task；无变化不新增历史；P09-02 |
| 4 | 删除 | 显示目标并确认，取消不改状态，ID不回收；P09-02 |
| 5 | 设置完成状态 | 明确设为已完成或未完成，无变化不新增历史；P09-02 |
| 6 | 筛选与搜索 | 分类精确匹配、优先级1/2/3、完成状态、标题子串，可组合，空条件不限；P09-02 |
| 7 | 排序视图 | 默认任务保存顺序；可按ID升序、优先级降序、标题码点升序；P09-02 |
| 8 | 统计 | 全部任务的总数、已完成/未完成、三档优先级、分类计数；空集合计数均为0；P09-03 |
| 9 | 导出 | 当前视图导出UTF-8 TSV，列顺序同列表，首行为列名；单独确认目标；P09-03 |
| 10 | 保存 | 当前路径，首次保存选择路径；完整校验/编码/原子写成功后更新保存快照；P09-03 |
| 11 | 打开另一文件 | 先处理未保存提示，再读入候选；全部成功才替换；P09-03 |
| 12 / 13 | 撤销 / 重做 | 只恢复任务列表，不降低next_id；P09-03 |
| 0 | 退出 | 有修改时保存/放弃/取消；保存失败留在会话；P09-03 |

搜索大小写敏感，保留Unicode原文，无正则或模糊匹配。排序稳定，相同键按当前存储顺序；筛选、排序只改变视图，不改磁盘tasks顺序、历史或dirty。排序使用既有查询order/yield（必要时普通ZZY循环），不能把Task数组交给array.sorted。列表、统计、导出均重新计算，不引入Lazy/结果缓存。

字段输入先收集候选再确认，不在多轮输入之间修改任务。标题/分类保留原文，trim仅判断是否全空白；长度和控制字符按v1校验。ID和优先级采用safe_int后检查范围，不把1.0或true当整数。确认菜单提供提交/重填/取消，避免占用可能合法的标题作为取消口令。任一提示收到EOF，丢弃未提交草稿，若会话dirty则输出未保存提示后结束，不写文件。正常业务失败仍是Result和菜单提示；资源错误/取消沿用运行时终止行为。

TSV导出含表头`id\ttitle\tcategory\tpriority\tdone`，行尾LF、Bool为true/false。已验证字段禁止Tab/CR/LF，因此无需偷偷改写标题。导出使用write_atomic，失败不宣布成功，不改变绑定文件/保存快照/历史；目标由用户明确确认，提示避免选择数据文件，拒绝与当前绑定路径字符串相同的目标。没有通用路径规范化接口，不能声称已识别所有软链接/大小写/相对路径别名；使用独立导出路径是操作约定。TSV不是v1存档，不支持作为任务文件打开。

## 数据结构与模块边界

| 模块 | 职责 | 依赖 |
|---|---|---|
| model.zzy | Task、Document、Session及快照结构；逐字段内容相等 | 无 |
| validation.zzy | 文本/整数/任务/文档分层校验，返回带路径的Result | model |
| tasks.zzy | 生成增删改/完成候选列表，不做I/O | model、validation |
| views.zzy | 筛选、稳定排序、统计、导出文字 | model |
| storage.zzy | read→parse→validate；validate→encode→write_atomic | model、validation |
| session.zzy | 编辑提交、历史、高水位、dirty、加载提交与保存快照 | model、tasks、storage |
| main.zzy | 菜单、字段输入、确认/恢复/EOF流程 | session、views |

上述七个模块均已实现，入口为main.zzy。模块图无环，按声明先后组织函数；use相对导入文件，普通I/O路径相对启动工作目录。所有业务逻辑、格式校验和状态提交用ZZY；Python仅作为现有解释器、通用文件接口与外部测试驱动。

Task字段顺序为id:Int、title:String、category:String、priority:Int、done:Bool。Document含next_id和tasks，磁盘编码另构造schema_version/next_id/tasks的Map；只有验证后才构造带注解Task。Session另外保存path（String或Null）、saved（最近成功加载/保存的值快照或Null）、undo/redo及视图条件。可空字段不编造联合类型注解，外部输入不用注解代替业务检查。

应用约定历史中的Task永不原地写字段：编辑用with新建Task，增删建新Array；历史array.copy浅快照安全仅因所有Task字段是标量。不能使用Array/Map/结构的==做内容相等；dirty逐字段比较tasks顺序、五字段、next_id及绑定路径。成功保存保留历史，随后撤销重新计算dirty；新建的saved为Null，首次成功保存才建立基线。

## 文件边界、加载与恢复

采用v1根对象恰好schema_version/next_id/tasks；任务恰好五字段。ID范围1..2147483647，next_id可到2147483648且严格大于现存ID；删除/撤销都不能降低会话高水位。任务最多10000、标题1..200码点、分类1..40码点，优先级1/2/3、done必须Bool。完整规则直接引用契约，不另创宽松格式。

固定校验流水线：

1. io.read_text取得Result，失败保留当前状态。
2. data.parse；严格JSON失败不猜测修复、不自动覆盖文件。
3. 根data.kind==map后检查必需键及未知键，再get；依次校验版本、next_id。
4. 确认tasks为array、长度合法才遍历；每项先kind==map，再存在性/字段集合，按id/title/category/priority/done顺序校验。
5. id校验为Int且在范围内之后，以str(id)作Map键去重；逐项建立新Task，记录最大id。所有失败携带如tasks[1].priority的路径。
6. 确认next_id>max_id；一次性替换Document与路径，清空undo/redo，建立保存快照并重置视图。前面任何失败都不能提交部分状态。

v1合法文档仅有根Map→tasks Array→Task Map三层容器，字段均标量；因此完整字段验证后天然满足最多四层。无须先对任意外部值做无限递归遍历。parse仍受默认value_depth=64和内存配额约束；非法深层字段按首个确定的类别/字段错误拒绝，触及解析资源限额则仍为E211。**不把全运行时value_depth收紧到4**，否则会错误限制Session/历史等内部结构。唯一应用配置覆盖是[limits.json](limits.json)的io_payload_bytes=4194304；输入文件从读取期间就受限，不先无限读完再检查。

有未保存修改时打开/退出先选保存、放弃、取消：取消不执行读写；保存失败停止后续加载/退出；放弃后加载仍采用候选事务，失败也保留原会话，成功才丢弃旧状态。若保存成功后新文件加载失败，则保留刚刚成功保存的旧会话（其dirty已清除），不能把已经完成的保存当成未发生。

读取失败提供重试、其他路径、保留当前；初始打开失败回起始菜单。首次保存需选择路径；只有write_atomic成功才更新路径/快照。所有失败保留内存修改，旧目标在原子替换前失败时保持。文件已存在时由用户确认覆盖，不推断操作系统错误文本；不承诺断电落盘或多写者合并。

撤销/重做最多100步，另受资源预算限制；每次真实编辑只入栈一次，新编辑清空redo，满100时丢最旧并提示。资源分配失败是E211，不能静默删更多历史掩盖失败。撤销新增后再次新增仍取更高ID；ID耗尽禁用新增但删除/读取/保存照常。成功加载清空历史，高水位来自新文档（禁止回退的范围是当前文档会话，加载新文件建立新状态）。

## 启动与验证

在项目根目录运行，Python入口使用已有虚拟环境：

```powershell
& ./.venv/Scripts/python.exe -X utf8 -m zzy check apps/zzy-campus/main.zzy --limits apps/zzy-campus/limits.json
& ./.venv/Scripts/python.exe -X utf8 -m zzy run apps/zzy-campus/main.zzy --limits apps/zzy-campus/limits.json
```

先选1新建，选2新增并依次输入标题、分类、1—3优先级、1提交。选10保存，首次输入路径并确认；选0退出。下次启动选2打开刚才的JSON即可恢复。保存路径可以含中文和空格；普通文件路径相对启动工作目录。建议使用专用数据目录，导出TSV用不同路径。

菜单0在子确认中表示取消；编辑采用完整字段重填，空白标题不会表示“保留旧值”。筛选分类和搜索允许空行表示全部。撤销新增不会回收ID；撤销到相同任务内容但next_id更高时仍显示未保存，这符合高水位持久化规则。

[demo-input.txt](demo-input.txt)给出新增两条、完成一条、统计、保存、退出的固定输入；其中写入campus-demo.json，运行前确认目标目录。可先创建并切换到独立演示目录，再以绝对路径指定解释器、main.zzy和limits.json。不要把用户现有数据当测试夹具。测试驱动会自动使用临时目录，无需手动复制样例。

测试覆盖说明及独立期望见[tests/p09](../../tests/p09/README.md)。最后一条包含所有既有语言/运行器测试，报告目录须已存在；数量边界测试要实际校验10000条任务，超时单列，不能用空收集或跳过报成功。
