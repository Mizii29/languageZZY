- 原生 CLI SHA-256 为 `f697f08b0336bb34522ff036ca98cb7d72e2cf1adbb3993d940ae25e43279add`，与 N6 一致。
- 阶段探针 SHA-256 为 `bfc49226c8b31d3230037e16560e4ce205e89eb421995f56f21ba6f4b8ba77f5`。
- 原始清单与两轮时序见 [基线归档](../results/native-n7/baseline.tar.gz)。每轮 432 条，其中 72 条预热、360 条正式。两轮均无失败、错误答案、计数器缺失或超时。另有 24 条预跑、12 条逻辑采集。

两个解释器在四组输入都保持 ZZY 的资源检查。三组长程序中，原生 ZZY 的纯执行比 Python ZZY 快约 2.5–3.2 倍，直接 Python 的纯执行比原生 ZZY 快约 202–316 倍。短脚本的完整原生 CLI 更快，三个长脚本的直接 Python CLI 更快。两种结论适用于不同的计时边界。

逻辑另采集一轮。以 X03 为例，原生峰值为 8 个计费对象、10016 个槽位、34911 字节逻辑负载，Python ZZY 为 8、10016、19755。具体表示和回收时机构成差异，逻辑计费键不能推导 RSS 或实际私有提交量。两个请求结束均检查相关逻辑用量归零。

范围包括短程序、标量算术、函数调用和保留数组，未测 Web、GUI、数据库、I/O 主导、机器间差异、冷文件缓存或手写 C。完整分段与离散程度见每轮 `summary.json`。复现见 [命令](README.md)。
