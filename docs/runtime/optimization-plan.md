# P11：现有解释器优化实施计划

建立：2026-10-29｜状态：已评估及自动验收，04/05撤回；人工按用户授权延期未验证｜前置：P10-01、P10-06 已完成｜后续：P12 验收交付

本计划落实用户选定的五项优化：诊断位置、资源计量、小整数、`array.sum/stats`、查询排序。阶段任务及勾选只维护在 [todo](../development/todo.md)，阶段依赖见 [roadmap](../development/roadmap.md)，真实操作写入 [开发记录](../development/development-log.md)。本文定义实施边界与完成标准，不是性能结果；P07 历史结果见 [实测报告](performance-report.md)，不得当作当前版本的收益。

## 1. 范围、顺序与取舍

当前实现已有不可变 Program、名称解析、局部槽位、闭包 Cell 和显式用户调用栈；Web 启动时已准备 Program，P10 合约已有独立验收。P11 保留 AST 执行链，在公共开销处逐项优化，不把这些已有能力再次算作新增成果。

| 顺序 | 任务 | 目的与前置 | 主要产物 |
|---|---|---|---|
| 1 | P11-01 冻结基线与对照方法 | 核对 P10 后的代码、契约、环境、测试清单；为后续每项建立可比较的实验 | 基线清单、正确性答案、剖析与独立计时原始记录 |
| 2 | P11-02 诊断位置按需生成 | 先减掉检查通过时的路径/行列构造；作为后续计量优化的基础 | 位置传递方案、诊断/并发/取消验证、单项对照 |
| 3 | P11-03 资源计量简化 | 在 02 后减少预留对象和计数更新开销 | 保持事务性与释放语义的计量实现、故障/边界验证 |
| 4 | P11-04 小整数带守卫快路径 | 使用 02/03 后的公共检查，优化常见整数操作 | 清楚的守卫、通用回退、数值与紧配额对照 |
| 5 | P11-05 分离 sum/stats 工作 | 依赖已验证的整数操作，避免 sum 维护无用 min/max | 保持逐项检查的库实现、B04 及 stats 专项对照 |
| 6 | P11-06 查询排序比较优化 | 公共执行开销稳定后，单独研究排序比较 | 有类型条件的比较路径、稳定性/取消验证、B07 对照 |
| 7 | P11-07 累计回归、报告与交接 | 汇总所有保留改动；排查组合退化后交给 P12 | 全量/安装/HTTP 证据、性能报告、实际人工结果或待测说明 |

严格按此顺序推进。每项先验证行为，再单独测量，记录保留或撤回决定，更新 todo/开发记录后进入下一项。后项使用前项已经验收的版本，不把五项混成一次无法归因的修改。

默认面向既有 Windows/CPython 支持环境、课程应用与本地 Web 使用；具体版本以 01 的实际记录为准。默认策略仍为 default-v1，校园应用使用自己的已登记配置。性能目标是减少已证实的重复工作；不预设加速倍数、不增加依赖或公开语法、不宣称提供新的沙箱/硬中止能力。维护上优先小范围改动和可审查的回退路径。

原 P10-03 的“小整数快路径”在 P11-04 单独落实，完整字节码/VM 仍延期；P10-08 中优化所需的有限对照在 P11 各项落实，完整引擎/变形测试项目仍延期。旧任务不删除、不重复勾选，理由与重启条件见 [P10 取舍](../features/innovation.md#6-p10-候选保留与取舍2026-10-29)。

## 2. 各项必须保持的共同契约

- 值、类型标签、任意精度 Int、有限 Float、共享身份、别名、求值/副作用顺序不变；Bool 不作 Int。check 不执行用户代码，错误不得提前到加载或检查阶段。
- 使用同一生效资源策略。保持合法/非法输入的接受与拒绝、E211 的键/上限/需求计数、错误阶段、源码位置及释放时机；资源优化不能把保守上界误当实际需求而拒绝原本合法的输入，也不能漏计已有临时工作空间。
- 保留取消安全点及可恢复清理：普通错误、ResourceExceeded、取消、宿主 MemoryError 等均不得留下预留、活动遍历、Frame、Lazy RUNNING 或句柄。优化不通过降低检查频率换取速度；若某项无法保持，保留该情形的旧路径。
- 复用 [诊断](../language/diagnostics.md)、[资源](resources.md)、[查询](../features/query.md)、[库](../language/stdlib.md) 与 [Web/合约](web.md) 契约。Program 可共享，计数、Reservation 和用户可变状态仍归单个上下文；不在共享 Program 写入请求路径、当前目录或运行值。
- 无性能收益、明显增加维护成本或无法证明契约等价时，撤回候选并保留真实记录。只有完成所选项的实验、验证和去留说明才可勾选；撤回意味着“已完成评估、未保留实现”，不能写成“已提速”。设计文档存在不足以勾选。

## 3. P11-01：冻结基线与测量入口

先读 todo/最新日志和 P10 证据，核对 Git 修订、差异、运行时源码哈希、依赖、Python/Unicode/OS/CPU、GC、生效策略及测试 ID。P10 保存的 2041 核心、23 HTTP/Schema 是接手核对起点，后续新增测试须正常增加，不能写死数量或删减旧 ID。既有报告只有在源码范围匹配时可复用；需重跑的内容明确记录，不能借历史通过证明新代码。

复用 [P07 方法](performance.md) 的固定答案与同工作量规则。01 先运行适用正确性预检，保存当前基线剖析和独立计时；新实验驱动、参考路径与命令实际建立后记录在对应 README，本文不虚构已有 CLI 开关。

| 工作负载 | 复用/补充 | 必须单列的成本或失败 |
|---|---|---|
| B01/B02/B03 | 标量循环、调用、已有数组遍历 | execute 与 initialize/cleanup/cli_total，不把输入构造藏掉 |
| B04 与 stats 专项 | sum、stats；空/单元素/重复/有正负数组 | 只求和与完整统计分别计时；逐项类型与部分和限额相同 |
| B07 与排序专项 | 重复键、升/降序、不同筛选率和 take | 快照/筛选/键求值/比较/投影；不能仅比较宿主裸排序 |
| 诊断/资源专项 | 成功检查、真实超限、预留/释放 | 热点定位和失败成本；不把只测空循环当端到端收益 |
| 真实已实现路径 | 校园 CLI、合约校验、默认/shared HTTP | 正确性与恢复冒烟；启动、业务执行、HTTP 延迟分开，短请求不预设可测收益 |
| 非目标回归 | B05/B06/B08/B09、Sketch/headless | 观察公共改动是否使准备、排序、状态机、Quantity、绘图退化 |

首次正式对照默认每组 3 次独立预热、15 个成功样本，同机串行交错 before/after，固定工作量/顺序种子，保留原始样本和 min/max/median/MAD。短任务需要批量时，批内每次状态也重建；两版使用同一驱动。失败、超限、超时保留，不填 0，不用截断后快样本计算“成功加速比”。更换规模/超时/策略时另记实验，不能与旧配置直接相比。

先用 cProfile 定位，正式计时关闭 profiler/跟踪器；内存诊断另做，逻辑预算、Python 分配与 RSS 分开。历史 P07 提升只适用于当时版本。01 输出当前测量矩阵与可复现命令；每项前后对照都记录确切修订/补丁哈希，不需要同时维护两个产品引擎。

## 4. P11-02：诊断位置按需生成

入口优先核对 `Interpreter.check/reserve/location`、`Token.span`、`Source.position/span` 及 ResourceMeter 报错链。当前成功路径也会准备文件名、计算 Token 起止行列。首选让成功检查只处理计数，失败时才解析定位；仅在实测值得时缓存不可变位置。

实现须区分 Token 范围与完整表达式 Node 范围，保留既有调用处的选择；覆盖 UTF-8/BOM、CRLF、中文/非 BMP 字符、EOF、缺位置、跨模块及调用/查询 notes。当前目录变化仍按原契约反映到显示路径，不把路径永久写入共享 Token/Program。必要的定位提供者只保留最少源码信息，不闭包捕获整个 Interpreter/Frame/用户值而延长生命周期。

若采用缓存，限定为源码/Token 数量相关的有界数据，说明额外内存；Program 共享时优先准备期只读数据或上下文本地缓存，不能无约束惰性写共享映射。失败/取消过程中仍能生成稳定诊断，提供者错误不能掩盖原配额错误。

验证完整文本与 JSON Lines、退出码、E211 位置/计数、cwd 改变和共享并发隔离；分别测成功热点和实际报错，不能只证明函数调用次数减少。

## 5. P11-03：资源计量简化

入口为 ResourceMeter/Reservation、Interpreter.reserve、Value/容器拥有者和 WeakSet 清理。按热点尝试单资源预留专用路径、先检查后统一更新以避免每次复制 `_used`、减少计数查找或对象字段；不要求把全部方案同时加入。

先列出未知键、非法计数、取消、限额和分配失败的原有检查顺序。多个资源预留必须全成或全不成：计数和 Reservation 创建/登记任一步失败均不得部分扣款或失去释放所有权。单上下文内部实现不等于可跨线程共享；各 Web 请求保持独立计量，不建立全局可变计数池。

release 幂等，with/异常/析构路径一致；保留即将超限时的循环回收，别名有效载荷不重复计费、引用槽仍计费。精简对象结构前检查弱引用能力、子类/动态字段及 Value.owners 的用途，不直接对所有 Value 加 slots，也不池化仍可达对象。

用 L-1/L/L+1、多项中间一项失败、取消/MemoryError 注入、重复释放、循环引用及连续上下文验证净计数与清理；另做正常标量/容器工作量计时，排除只在空计量微基准上获益的方案。

## 6. P11-04：小整数带守卫快路径

先聚焦 Int 加/减，乘法等仅在本项有明确证据且能单独审查时加入。进入条件必须明确、可测试：两个实际值均为 ZZY Int、操作属于支持集、位宽与资源空间足以保证该路径合法。注解不是删除运行检查的依据，不把 Int 改成固定宽度机器整数。

保守位宽上界只用于证明“可以安全走快路”；接近整数/载荷限制、符号或操作不在支持范围时，在改变状态前回到现有精确算法。不能因上界偏大就拒绝实际合法的结果，不能先分配未计量的大整数再补检查。临时空间和结果载荷仍按既有规则处理；若暂时无法保持完全相同的配额计数/失败行为，缩小守卫范围。

验证零/正/负、进位/借位、跨字节位宽、抵消、极大整数及 Bool/String/Float 排除，紧预算恰好成功/超一失败，错误位置和取消清理；用固定期望加通用路径对照，随机/变形只作补充。测小整数常见循环、大整数回退与守卫未命中成本，保存命中比例，不根据一个小循环推断全解释器提速。

## 7. P11-05：分离 array.sum/stats 工作

入口为 `Library.native_call` 中两个函数的共用循环。让 sum 仅校验/累加；stats 继续计算 count/sum/min/max。可共用必要的检查与整数操作，避免复制两套规则。接口、只接受 Int、空 sum/count 为 0 与空 min/max 为 Null 均不变。

保留逐项类型检查、部分和整数位数/载荷检查、取消和错误定位，不直接以 Python 裸 sum 替代。减少临时 Value 仅在生命周期与配额能证明等价时尝试，不作为本项必须扩大的范围。不加入 P10-07 类型缓存，也不缓存旧统计结果。

验证空数组、单项、正负与重复值、中途 String/Bool、部分和先超限而最终抵消、输入与别名未变、失败后恢复。B04 与 stats 专项分别测三档规模；核对 Python 对照包装同样执行类型/部分和约束，不能只优化一侧的工作量定义。

## 8. P11-06：查询排序比较优化

当前 `Features.query_value` 已逐项保存排序键；优化对象是 `cmp_to_key` 比较期间反复经过通用 binary 的成本，不把“一次求键”重复算作新增能力。优先为已完成类型检查的普通数值/String 提供直接比较，Quantity 保留通用路径。

候选可以是专用比较器或宿主 key 排序，依据等价性与测量选择。若宿主原生比较过程无法保留足够取消安全点，使用带取消检查的专用比较器；不得悄悄牺牲响应能力。Int/Float 混合沿用原比较规则，不统一转 Float；相同键、降序都保持稳定。Quantity 的量纲/精确比较不在此项中重写。

保留浅快照→求 take→完整筛选→完整排序键校验→稳定排序→截取/投影的契约。take=0 或很小不能跳过后部错误，不使用会改变阶段/错误顺序的 top-k 或流水线。临时索引、键及排序工作空间仍预留，取消/失败恢复 current_item 和全部预留。

测试重复键升/降序、混合数值与大整数精度、String/Quantity、空集/全过滤/take 边界、后部非法键与查询输入下标 notes、紧配额、真实排序中取消和随后恢复。对照完整记录顺序和输入未变；测 B07 与键分布/筛选率/take 专项，而非只比较预构造 Python 列表。
