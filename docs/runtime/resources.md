# ZZY 资源限额与执行边界

更新：2026-10-14｜策略版本：default-v1｜状态：P06 已验证全部生效键的小配置边界及关键默认边界；具体证据和未测范围见文末

本文件细化 [syntax.md](../language/syntax.md) 的 E211，不增加语言关键字。以下数值是可调整的工程起点，不是已经测出的安全容量或性能结论；调整须更新策略版本和验证记录。性能报告必须保存实际生效配置，不能只写“使用默认值”。

## 1. 默认限额

KiB 为 1,024 字节，MiB 为 1,048,576 字节。容量允许等于上限，尝试超过时失败；多个限制同时适用。下表的前端总量针对一次入口及其完整依赖图，运行总量针对一个 ExecutionContext，测试的每个独立上下文重新计量。

| 配置键 | default-v1 | 计量和检查位置 |
|---|---:|---|
| source_file_bytes | 2 MiB | 每个源码文件的原始字节，包含 BOM；增量读入时检查 |
| source_total_bytes | 16 MiB | 规范路径去重后的入口与依赖字节总量，缓存命中也检查 |
| module_count / import_depth | 128 / 32 | 唯一模块数 / 活动导入链长度，入口计 1 |
| tokens_per_file | 250,000 | 每文件非 EOF Token 数，生成下一 Token 前检查 |
| ast_nodes_total | 500,000 | 完整 Program 的 AST 节点数，创建节点前检查 |
| syntax_depth | 64 | 源码表达式/块嵌套层数及 AST 最长父子链边数分别检查；叶节点为 0，消去分组括号也不能绕过源码嵌套检查 |
| numeric_digits | 4,096 | 数字转换输入中的数字总数；计前导零，JSON 指数数字也计入，不计符号/小数点 |
| integer_bits | 65,536 | Int 绝对值的二进制位数，0 为 0；Quantity 分子/分母和算术中间整数同样检查 |
| quantity_exponent_abs | 64 | Quantity 每一维量纲指数的绝对值 |
| call_depth | 64 | 活动 ZZY 函数调用与 NEW Lazy 唤醒层数之和；内部尾调优化不改变语义计数 |
| value_depth | 64 | JSON、调试显示、冻结等遍历的复合值嵌套层数，根容器计 1；循环检测另行进行 |
| container_items | 1,000,000 | 每个 Array 的元素数 / Map 的键值项数，扩容或创建前检查 |
| text_codepoints | 4,194,304 | 每个运行时 String 的 Unicode 码点数；读取、拼接、转换都检查 |
| io_payload_bytes | 16 MiB | 每次文本文件读写、JSON 输入/编码输出的 UTF-8 字节数；与 String 限额同时满足 |
| runtime_objects | 200,000 | 本上下文在用的 Array/Map/结构/函数/Lazy/Machine/原生值对象数 |
| runtime_slots | 2,000,000 | 在用容器项、帧/Cell 引用、查询快照/排序缓冲等逻辑槽总数；Map 每项按键和值两个槽计 |
| runtime_payload_bytes | 128 MiB | 在用标量有效载荷及宿主临时缓冲的逻辑预算，见下文；不是进程 RSS 上限 |
| stdout_bytes / stderr_bytes | 各 1 MiB | 本次执行产生的 UTF-8 字节，含换行/提示；输出前检查 |
| program_cache_entries / program_cache_bytes | 32 / 64 MiB | 进程准备缓存的条目数与实现记录的估算字节，满时淘汰而不是使用户程序失败 |

原生 CPU 栈深度不能直接代替 syntax_depth/call_depth。实现须在支持平台验证允许的边界；必要时使用显式栈，不能为某条递归路径悄悄降低已公布限额。剩余宿主 RecursionError/MemoryError 作为 E211 兜底，不宣称进程被操作系统终止时也一定能输出诊断。

在用计量按实际拥有的存储计费：共享对象有效载荷只计一次，每个引用槽仍计费。String 按 `4 × 码点数`、Int 按 `ceil(bit_length / 8)`、Float 按 8 字节计；Bool/Null 无额外有效载荷，Quantity 计分子/分母及维度整数，宿主临时字节缓冲按实际字节计。对象/槽的开销由另外两项限制约束，不重复称为精确 Python 堆大小。分配前预留，失败释放预留，销毁或确认不可达后退还；禁止只限制单个数组却允许无限创建数组。基线先不池化运行时对象，引用环的回收也须纳入验证。

宿主整数转十进制另受宿主有效数字上限约束；启动时记录该值，与 numeric_digits 取更严格者作为十进制转换限额，0（宿主未限制）不放宽 ZZY 的 4,096。同一生效限额用于源码、JSON、safe_int 及整数输出；计算所得大整数可以继续计算，但转文字可能 E211。不能全局关闭宿主限制，也不能将容量超限当格式错误 Result。

## 2. 配置与失败处理

P00 的宿主配置已建立 `ResourcePolicy`，默认采用此表。CLI 参数为 `--limits <json文件>`，只在入口读取，不允许 ZZY 程序修改。配置使用 `policy_version: 1` 和 `limits` 对象；仅覆盖已知键，未列键沿用默认。只接受正 Int（排除 Bool），未知字段、重复键、未知版本、非整数、0/负值和不支持的组合报 E401、退出 2。文件最多 64 KiB，不递归包含其他配置，不隐式读取环境变量。当前可用于 info/source-info/lex/run/check/test。check 仅消耗前端预算，不分配运行上下文、不触发运行期容量检查。

P00 配置使用严格 UTF-8 JSON（不带 BOM），顶层两个字段均必需；每个覆盖值支持 `1..sys.maxsize`，本次 64 位宿主为 `1..9223372036854775807`。这是配置表示范围，不保证实际机器能分配相应内存。生效指纹为 `effective_record()` 的键排序、紧凑 UTF-8 JSON 的 SHA-256，包含 policy_version、profile、limits、host_decimal_digits 和 effective_decimal_digits；可通过 `python -m zzy info` 取得。

JSON 中的容量使用整数基本单位，不接受字符串 `"2 MiB"`；表内以 `/` 并列的名称是两个独立键。最小示例（仅覆盖三项，其余仍用默认）：

```json
{"policy_version":1,"limits":{"source_file_bytes":2097152,"call_depth":64,"stdout_bytes":1048576}}
```

配置值超过该宿主实现能表示/执行的范围时应在入口明确拒绝并说明范围，不能静默截断；允许某项单体上限高于总量上限，此时二者共同生效。配置指纹对所有补齐默认后的有效值和宿主十进制限制计算，键排序、紧凑编码，不因 JSON 字段顺序变化而不同。

运行器每例传入同一策略；小限额用例显式覆盖，报告保留生效配置及其规范 JSON 哈希。准备结果缓存也纳入该策略指纹，防止宽松配置准备好的 AST 在更严格的 check 中绕过限制。内存缓存满时使用 LRU 淘汰未固定条目；正在运行的 Program 仍由上下文持有，其存活容量不冒充已经释放。

前端/准备阶段超限为 E211、退出 2；执行阶段超限为 E211、退出 1；测试子进程的预期错误按清单比较，运行器整体有失败才退出 1。诊断包含限制键、上限与本次需求/计数，不输出完整巨大值。stderr 超限后允许单独预留的最多 4 KiB 最终诊断，只报告一次，避免“报输出超限又产生输出超限”的递归。JSON 模式先缩短 message/notes 再编码，保留必需字段和完整换行记录；不能直接截断 UTF-8 字节或半个 JSON 对象。

分配上界用于证明快路径可用；上界估计超过预算但实际可能未超限时，回退到逐步受限路径。大数、Quantity、JSON、排序与宿主批量操作都遵守中间空间限制。优化器自己的折叠预算耗尽仅放弃优化，不能取代这里的程序资源限制。

资源中止释放活动遍历计数、Lazy RUNNING 标记、临时文件、句柄与会话；不回滚已经输出的文字或已完成的普通文件写入。文件原子发布只保证提交前失败保留旧目标，提交后不伪报“完全没写过”。

## 3. 时间、中断与扩展

内存/深度限额不会停止无分配的无限循环。默认 `run` 不设置墙钟截止时间，以免菜单或绘图等待被误判；Ctrl+C 走统一取消清理，CLI 退出 130，不转成业务 Result。测试运行器默认每例墙钟 10 秒、stdout/stderr 各 1 MiB，可由清单明确覆盖；超时终止并回收进程树，记失败、运行器退出 1。持续输出不能通过简单截断而判成功。

普通运算/循环/调用和分块宿主操作在安全点观察取消。阻塞输入或单次宿主调用不能假设可被解释器计数器强行打断；测试硬超时依靠进程隔离。P10 语义步数配额仍为可选，不把本次容量和取消约定称为完整沙箱，也不限制脚本已获准的文件访问范围。

sketch 启用时另有初始扩展限额：每画布已提交路径段 1,000,000、历史命令 100,000、历史有效载荷 64 MiB，每方向待处理事件/渲染消息 4,096 条且总有效载荷 16 MiB；与上下文总预算同时检查。超额在提交前 E211，关闭/取消信号走独立控制路径。历史满不静默淘汰；曲线展开、检查点、复制缓冲也计量。100,000 笔画基准若先触发资源限制，应如实记录并单列提高配置的实验，不偷换默认限额。

## 4. 实现和验收映射

- P00 建立配置、计量与信号接口；P01/P02 实现前端和基本值限制；P03/P04 覆盖调用、捕获、Lazy、查询/数量；P05 统一库边界；P06 完成 RESOURCE-01/02；E 阶段加入绘图计量。
- 每项上限用缩小配置验证 L-1、L、L+1；按该指标设计独立输入，避免先触发其他限额。另测别名不重复计有效载荷、引用槽仍计费、取消后清理和紧限额缓存命中。
- 默认配置也需在目标 Python/OS 上验证关键边界；黑盒检查外部错误/退出码，原生层检查内部计量释放。P00 已验证默认源码/输出边界，其他语言分配点尚无结果，不以计量接口通过代替语言验收。

P00 的 ResourceMeter/Reservation 是单上下文内部接口：预留前检查全部请求，失败不部分计费，拥有者释放或通过 with 在退出时退还，取消信号不被普通 Exception 捕获。SourceLoader 在一次准备会话内保留规范路径去重的同字节快照，结束会话释放源码计数；它不是跨 Program 的准备缓存。后续值分配器仍需落实共享载荷、引用槽、循环回收和缓存生命周期，P00 不宣称这些功能已实现。原生元数据注册结构与运行实现分开，P01-02 只注册可调用的 io.print 元数据与实现，不加载 GUI；其他库/扩展仍待实现。

P01-01 在 Lexer 中落实每文件非 EOF Token 上限、ASCII 数字位数（包含前导零和小数两侧）与解码后的字符串码点上限，超限 E211/2。Token 保存源码偏移，数字不转宿主数值；EOF 与注释不占 Token 配额，重新扫描另一文件使用独立计数。长名字、字符串与注释扫描有取消检查点；数值位数和字符串长度检查同时观察取消。P01-02 的后续接入见下段，其他语言值的计量仍不能只凭接口存在视为完成。

P01-02 在节点创建前检查 AST 总数与父子链深度，另检查源码括号嵌套；Program 和语句也计节点/边，显式分组保留 AST 节点。准备阶段只转换受数字长度限制的 Int 字面并检查 integer_bits，运行时加法预先计算精确结果位数，拼接预先检查码点数及载荷预算。io/print 初始对象、绑定与参数引用槽、Int/String 在用载荷及打印临时文本接入 ResourceMeter；别名共享 Value，不重复计其载荷，替换后无引用的值退还预算。当前使用已验收 CPython 的引用生命周期，异常/取消时上下文还会统一释放存活预留，避免 traceback 延长计费。

P01-02 当时仅有无环的标量/只读命名空间值；Array/引用环的后续 P02 验证见下文，Cell/闭包见本文件 P03 补充；Lazy 的 P04 证据见文末；Map/模块的 P05 证据见文末；缓存仍待后续阶段验证。标量对象的 Python 开销不计成 runtime_objects，符合表中分类；这套逻辑预算不等于 Python RSS。整数位数探测、打印格式化的临时存储也计预算，已有输出失败时不回滚。

P02 补充：Float 载荷、数组对象/元素引用、结构实例/字段及定义引用、Range 边界引用、块/循环绑定和按需加载的原生函数接入同一上下文计量。数组替换只增加内容版本，push/pop 同时增加结构版本与内容版本；容量或活动遍历拒绝发生在写入前。释放预算前确认不可达，配额将超限时先执行环回收；上下文退出统一释放存活预留，活动计数使用 finally 清理。

有符号加减使用精确宽度探测；乘法在上界可能误拒绝时回退到分块精确位数探测，工作缓冲与结果转移计量。调试显示采用受限片段，根复合值计深度 1，活动路径检测循环；重复但不成环的引用照常显示。io.input 逐码点有界读取，单次输入以 io_payload_bytes 限制 UTF-8 字节（包含行结束符），text_codepoints 限制去掉 LF/CRLF 后的内容；多次调用不共用单次输入额度。提示计入 stdout，读取/编码故障 E401、超限 E211，均不伪装 EOF。这里明确的是 P02 绑定到既有策略键的计量方式，不增加配置键。

本阶段验证了数组容量/输入长度与字节的相邻边界、默认值显示深度 63/64/65、别名、引用环回收、状态复用、版本与异常/取消清理，映射见 tests/p02/README.md。Cell/闭包的后续证据见本文件 P03 补充；Lazy 的 P04 证据见文末；模块的 P05 证据见文末；完整 RESOURCE-01/02 与缓存仍待后续阶段；逻辑预算不等于 Python RSS，真实终端 Ctrl+C 尚未验收。


## P03 函数与捕获计量

P03 函数值计一个 runtime_object，捕获引用与函数注解持有的名义类型引用计 runtime_slots；共享 Cell 的内容计一个槽位。调用前为整个静态局部槽位数组及自身函数引用预留容量，块结束清除该块槽位；只有捕获的可变绑定使用 Cell，其他局部直接存值。实际捕获者保留 Cell，离开定义栈帧不提前释放；传递捕获也进入布局。模块绑定仍使用词法身份桥接，不以名字动态回溯调用者。

用户调用由 AST 生成器交给显式调用栈驱动，进入前检查 call_depth，返回/异常均恢复上一 Frame 并清除局部。原生调用不增加 ZZY 调用深度；未来 NEW Lazy 唤醒须在 P04 共用此计数。驱动器不持有已结束请求或已丢弃返回值；用例同时验证丢弃后的释放与仍可达闭包的保留。

P03 已验证默认 call_depth 的 63/64/65、syntax_depth=64 与 64 层调用组合、缩小后的调用/槽位/对象配额相邻边界、Cell/闭包引用环回收、返回/诊断/取消/资源/内存失败后的 Frame 和活动遍历清理。证据见 [P03 测试映射](../../tests/p03/README.md)。这是本机逻辑预算验收，不是 RSS 上界；Lazy 的 P04 证据见文末；模块的 P05 证据见文末；缓存、完整 RESOURCE-01/02 与其他宿主平台仍未验证。

## P04 特色值与查询计量

Lazy 沿用闭包捕获/共享 Cell，另为缓存预留一个槽位；NEW wake 与函数共用 call_depth 和 Frame，READY/FAILED 不重执行。普通诊断缓存保留原位置；取消、配额与宿主中止恢复 NEW，结束后释放 Frame/配额。Result 计载荷引用槽位，Machine 定义/实例计对象，实例保存定义及状态两个槽位；成功转换先完成 String/Result 分配，后写状态。递归冻结的内部宿主边界已测，P05 模块/Map 证据见文末，公开共享上下文接口仍待 P08。

Quantity 使用 Fraction，分子/分母/指数计 payload；字面检查 integer_bits，运算交叉约分并检查中间整数乘积，指数检查 quantity_exponent_abs，不降级成 Float。查询在快照、索引、键/排序临时缓冲和结果分配前预留；排序键在投影前释放。P04 测试覆盖缩小限额相邻值、失败/取消清理；完整默认大容量压力矩阵仍留 P06。spec 每例独立预算，收集字节快照受 source_total_bytes/module_count 总量约束，父进程输出也受预算。


## P05 库与依赖图计量

Map 按对象、键/值引用槽及保留的 String 键载荷计费；覆盖旧键不增加元素数或改变插入顺序。文件按实际 UTF-8 字节限制，读取过程中检查字节与码点数量；字符串拼接/分割、JSON 缓冲、排序临时引用及返回对象均预留空间。JSON/safe_int 的整数转换按受限累加检查中间位数，超限保持 E211；不降级为格式失败。取消和宿主内存中止穿过库边界，运行结束清理全部预留。

模块路径规范化后同一准备过程去重，依赖总字节/数量与根深度 1 一起计费。spec 收集保存每个入口的完整图，worker 使用收集快照且重新应用同一策略，运行状态不共享。默认 import_depth 的 32/33、JSON value_depth 的 63/64/65，以及缩小配置的 module_count/source_total_bytes/io_payload_bytes/integer_bits/container_items 已有测试；完整默认大容量逐项矩阵仍待 P06。缓存优化、其他 Python/OS 与实际 RSS 上界未验证，不能把逻辑预留计数等同进程内存。

## P06 验收证据与未测范围

## P08-01 HTTP容量

HTTP子集的流式body/响应64KiB、元数据16KiB、受控并发、取消与关闭边界统一见[Web契约](web.md)。每请求新ResourceMeter，io_payload_bytes=65536，其余default-v1不变；线程取消不承诺强制终止任意阻塞宿主调用。

P08-02共享模式增加服务自有计量，快照接管初始化预留，所有请求结束后关闭释放；每请求独立计量并预留绑定/模块映射槽。冻结数组遍历不写active，默认可变数组仍使用活动遍历保护。服务与每个请求各自受default-v1及Web覆盖约束，不宣称进程RSS硬限。

P08-03嵌入的每次call独立ResourceMeter；输入转换和Python输出树构建均计运行对象/槽/载荷，深度/容器/字符串/整数沿用现有键，重复别名展开不能绕过预算。stdin有io_payload_bytes及临时载荷检查，stdout/stderr保留原输出配额。结果返回后由宿主拥有，全部ZZY预留在finally归零；模块close释放准备快照，活动调用时明确拒绝close。残余宿主MemoryError/RecursionError按现有CLI原则报告E211，不伪装数据转换失败。

P08-04/05本轮新增SQLite事务与独立任务示例；实际db签名、提交/回滚与取消边界以docs/runtime/web.md为准。SQLite专项、真实HTTP重启、安装和完整回归证据见tests/p08；当前验收状态见todo。
