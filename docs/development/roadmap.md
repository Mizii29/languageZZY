## 2. 固定约定：后续 Agent 不要随意改名

- 宿主语言是 Python，ZZY 文件使用 `.zzy`，代码块使用 `{}`，普通语句以 `;` 结束，函数/结构/控制块后不另加分号。
- 声明使用 `(zno)`、`(zyes)`；函数使用 `(addnew)`；分支使用 `(zif?:)`、`(zzif?:)`、`(zzyf:)`。所有语言关键字保留半角括号形式。
- `:=` 表示初始化，`<-` 表示修改，`==` 表示比较；库函数仍写成 `io.print(...)` 等普通调用。
- `(zno)` 只禁止重新绑定，不等于冻结数组、结构和所有嵌套数据。
- 普通字符串使用 `[OoO]` 转义；`(raw)` 跳过转义；`/` 仍是除法或 URL 中的普通字符。转义在加载源码时处理一次，JSON 使用标准 JSON 规则。
- C/D 已选：`(machine)` 和 `<<` 定义/推进状态，`数值::单位` 为精确数量；规则见 [machine-units.md](../features/machine-units.md)，A 已选，`?>` 集合查询见 [query.md](../features/query.md)；B 未采纳。
- E 已选：sketch 绘图扩展见 [sketch.md](../features/sketch.md)，核心语法不变，E1—E4已全部验收，sketch ABI 1.0；其他新增场景未采用。
- 注释使用裸 `zzysay:` 和 `zzysayalot:` … `zzyend`，不加括号；完整词边界、多行不嵌套和未闭合诊断按 syntax 契约实现，`#` 不作 ZZY 注释。
- 先做 AST 树遍历解释器。字节码、NumPy、自适应优化是后续选项，不能作为实现基本功能的前置条件。
- 无实测结果时只能写“预计”“待验证”，不能写已经提高了多少倍。

## 3. 执行方式和任务状态

从待办清单中选择最早的、依赖已经满足的任务。每项任务完成后，补相应测试或示例、运行适用检查、更新待办和开发记录，再进行下一项。任务较大时可以跨多次执行接续，不需要从头重做。

普通实现选择按现有约定自行决定，并在记录中说明。技术完成标准用于检查质量，不是要求每阶段重新询问用户是否允许继续；用户的新指示优先于本计划。

如果出现失败，先记录真实现象并修复；未验证的任务不要勾选完成。暂停交接时写清当前文件、未解决问题和下一项可执行任务。性能收益与功能状态分别记录：功能能运行，不代表优化一定有效。

代码、测试和相关说明应形成有意义的 Git 提交。接手已有修改时先识别其来源，保留用户工作；不要伪造历史、为凑提交数拆空提交或默认推送远端。

## 5. 核心开发主线

### P00：把约定和开发环境准备好

**要做什么：** 先确定“机器接受什么输入、输出什么结果”，避免多个文件分别猜测规则。

- 检查本机 Python、Git 和现有文件，记录实际使用的版本；核心解释器优先使用标准库。
- 建立 `zzy/`、`tests/`、`examples/`、`benchmarks/` 等目录，以及包入口、项目配置、忽略规则和运行说明。
- 统一资源策略与内部控制信号：源码/数字/Token/嵌套/依赖/容器/输出在分配前或过程中有界；前端 E211 退出 2，执行 E211 退出 1。核心分配限制不等待可选 P10 请求步数配额。
- 采用 [resources.md](../runtime/resources.md) 的 default-v1、配置校验与生效指纹；记录 Python/Unicode/平台和已验证支持范围，明确工作目录与 use 路径差别，不静默 chdir。
- 复核已编写的 `docs/language/syntax.md` 与 `docs/language/stdlib.md`，确认 Lexer、Parser、Resolver 的实现边界、固定符号、优先级、求值顺序和错误码。文档存在不代表 P00 骨架已完成。
- 明确 `io.print`、输入 EOF、数值运算、条件 Bool、数组越界、结构默认值、求值顺序等可观察行为。已有文档没说清的细节，采用简单一致的规则并写入契约。
- 设计统一诊断和 CLI：成功退出码 0；运行时错误或测试失败 1；前端分析或参数错误 2；用户 Ctrl+C 取消 130。按 [diagnostics.md](../language/diagnostics.md) 统一文本/JSON Lines 与位置，测试预期非法源码仍可通过，测试汇总失败时使用 1。
- 为现有设计与项目骨架建立真实 Git 提交，记录提交标识。

**交付：** 包骨架、运行说明、正式语法初稿、首批提交。**完成标准：** 包入口可以显示帮助，文件读取和文件缺失有明确处理；语法表没有新旧关键字混用。

### P01：先让一段小程序真的跑起来

**要做什么：** 接通“读文件 → 切词 → 语法树 → 执行 → 输出”，先做小范围的完整链条。

- 支持整数、字符串、`+`、声明、赋值和 `io.print`。
- 实现源码位置、Token、最小 AST 和执行器；这一阶段可以先用简单名字表保存变量。
- 支持当前关键字和 `[OoO]`、`(raw)`，保留括号、数组符号和颜文字的识别边界。
- 支持两种 zzysay 注释，补 LEX-02 正常/错误样例；保持原文换行与定位，字符串内不误识别。
- 创建第一个 `.zzy` 示例；加入通过 CLI 执行的黑盒测试及错误源码样例。
- 建立测试运行器雏形：Python 负责启动解释器和比对结果，实际被测试的程序用 ZZY 写。

**完成标准：** 文件能输出 `5`，非法字符、未闭合字符串、错误转义和缺分号能够定位。`check` 可以分析而不执行打印。

### P02：补齐数据和控制流

**要做什么：** 从“计算器”变成能处理集合、选择和重复任务的语言。

- 增加浮点数、布尔、空值、比较和逻辑短路；明确整数与 Bool 的区别。
- 完成三种分支、`(while)`、`(for)`、区间、`(break)`、`(continue)`。
- 完成数组、索引、元素修改和增删；遍历期间通过任何别名的增删/重排均在动作发生前拒绝，错误退出释放遍历计数。
- 完成 `(shape)`、字段约束、默认值、`Type::{...}` 和浅层 `(with)`。
- 接入 `io.input`，添加输入输出、空集合、越界、除零及类型错误的黑盒用例。

**完成标准：** 可运行成绩统计或菜单小例子；短路跳过副作用；结构数组字面默认每实例新建，引用外部数组默认按语义共享，两类行为都有用例。

### P03：完成函数和作用域

**要做什么：** 给每次调用建立独立工作台，并提前确认变量属于哪个“房间”。

- 完成 `(addnew)`、参数、返回、匿名函数、自递归、可选类型注解和闭包。
- 实现 Resolver：重复声明、名称遮蔽、未声明名字和控制流上下文检查。
- 将局部变量定位到槽位；闭包和 Lazy 捕获的可变绑定采用共享 Cell，普通局部不统一套包装；循环每轮绑定独立。
- 检查实参个数、返回类型、局部变量隔离和闭包共享修改。
- 第一版按现有约定支持自递归，不支持未经预声明的相互递归。

**阶段边界澄清（P03 验收）：** 上述 Lazy 捕获指 P03 建立与函数共用的捕获布局/Cell 基础；Lazy 语法、捕获分析接入、状态与唤醒执行在 P04-02 实现并验证。P03 不宣称 Lazy 可用，也不免除 P04 的捕获义务。

**完成标准：** 递归与闭包例子正确，多次调用不串变量；函数内不能跳出调用者的循环。迁移槽位后原有黑盒测试仍通过。

### P04：实现 ZZY 的特色和测试语法

**要做什么：** 让可爱的符号拥有可验证的行为。

- 实现 `(^_^)`、`(T_T)`、`(?_?)` 和 Result 函数中的后缀 `?`。
- 实现 `(zzz)` / `wake`，包括未求值、求值中、缓存值和缓存错误状态。
- 实现 `~>` 和唯一直接参数插槽 `@`；左侧只求值一次。
- 实现 P04-06 状态机和 P04-07 数量，按 machine-units 补重复边/失败无修改/冻结/单位换算/精确小数/量纲错误；在 P04-05 验收前完成。
- 实现 P04-08 集合查询，补源求值一次、条目纯性、稳定 desc、空集/take=0 和错误顺序；在 P04-05 前验收，核心查询不依赖 P05 的纯库函数。
- 实现 `(o_o)`、`(@_@)`、`(spec)`；观察输出到标准错误，每个测试建立独立状态。
- 增加求值次数、失败提前返回、Lazy 不自动刷新和循环唤醒等测试。

**完成标准：** 特色示例可运行，失败有源码位置；不能只有成功例子而缺少副作用和边界验证。

**P04 范围核对：** MACHINE/UNIT/QUERY/TEST 覆盖类别包含后续阶段接口。本阶段验收核心、内部冻结、状态/临时目录/stdin 隔离；unit 库、模块导出、JSON 和文件库隔离留 P05/P06，不能据 P04 完成标记推断这些接口可用。

### P05：提供宿主库和模块

**要做什么：** 把批量处理交给成熟工具，让 ZZY 应用能够拆成多个文件。

- 建立明确的 Python 宿主函数注册表、参数校验和返回值转换。
- 完成 `io`、`array`、`text`、`math`、`data`、`unit` 的约定接口，先做 `sum`、排序、拼接、JSON 等常用操作。
- 按标准库契约完成 `(Map)`、`data.map/has/get/set/keys/parse/stringify`，不加入字典字面量；严格拒绝非标准 JSON，后端复用这套表示。
- 标准库 v0.6.1 加入 data.kind 的闭合类别，供 ZZY 应用在索引/构造前检查数据；不自动加入查询白名单，不把业务校验交给 Python 专用接口。
- 定义 `array.stats` 的返回结构和空数组规则，完成一次遍历版本；加速结论留到 P07 测量。
- 实现 `(use)` / `(as)`、函数/结构/状态机定义导出、同一环境复用和循环导入诊断；不将可变状态机实例缓存进共享 Program。
- 查询纯调用按 query 白名单登记实际原生绑定，遮蔽/动态调用不得凭拼写放行；用既有模块导出查询封装函数。
- 回调统一经过 ZZY 调用接口；宿主函数不能绕过类型和修改规则。
- 实现 `io.read_text/write_text/replace_file/write_atomic`，使核心 CLI 应用可保存加载；原子写入由宿主独占创建临时文件、关闭后替换，普通覆盖写入分开测试。
- 复核已编写的 `docs/language/stdlib.md`；sum/stats 仅接受 Int，空统计 min/max 为 Null，接口实现后才标记可用。

**完成标准：** 手写循环与库调用结果一致，排序不改变原数组；模块加载和测试运行之间的状态不会混用。

### P06：完成黑盒测试与人和 AI 的指南

**要做什么：** 让别人能独立验证并使用语言，这一阶段直接对应作业的测试和文档评分。

- 按已编写的 `docs/development/test-coverage.md` 建立实际用例映射，每条规则对应正常、边界和适用错误场景；补固定答案与变形关系测试。
- 正常功能使用 ZZY `.zzy` 程序和 `(spec)`；非法源码也保存为 `.zzy` 样例，期望错误放在运行器清单中。
- 测试输入、标准输出、标准错误、退出码、求值顺序和状态隔离；不依赖解释器内部 AST 或私有对象判断通过。
- 将 diagnostics 的四个期望样例纳入实际清单，补 CLI-02、RESOURCE-02、JSON-02；验证错误定位、类型类别、限额边界和紧配置缓存，不能用文档样例冒充实际输出。
- 有界读取 stdout/stderr，超额判失败；超时/取消后回收子进程与其派生进程、文件句柄和临时目录，不能留下 GUI/服务阻塞下一用例。
- 完成一条命令执行全部测试；汇总数量，任何失败均返回非零，不能把没有收集到用例当成成功。
- 对照实现复核正式语法与已建立的 [语法参考](../../skills/syntax.md)、[人用指南](../../skills/guide.md) 和 [AI 指南 / SKILL](../../skills/zzy/SKILL.md)；将草稿中的示例与命令落实为可运行文件，补真实验证记录及能力状态。AI 文档按任务引用 docs，不另复制正式契约。
- 为 Agent 准备独立练习任务，用实际运行结果检查它能否仅依靠指南编写程序，并记录遇到的问题。

**完成标准：** 功能覆盖表无未解释的空缺，所有现有黑盒测试通过；指南中的示例均有验证记录，计划接口与可用接口明确分开。

### P07：测出性能，再选择优化

**要做什么：** 得到可靠对照，再减少确实昂贵的重复工作。
