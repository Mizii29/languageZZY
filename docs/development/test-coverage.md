Lazy 的 FAILED 状态复用需宿主层用例或后续公开嵌入 API 验证：当前语言普通运行时错误会结束 run，没有 try/catch。ZZY 黑盒先覆盖首次错误、循环唤醒与作为普通值的失败 Result 缓存，不伪装可在致命错误后继续执行两次 wake。

ARRAY-02 致命异常后同一上下文的计数清理也由原生层/后续公开嵌入 API 检查，普通 ZZY 不能在致命错误后继续 pop。ZZY 黑盒验证正常结束/break 后可修改，以及错误即停止的外部期望；不把内部清理义务伪装成可运行脚本。

## 2. 运行器与外部期望

当前外部入口为 `python -X utf8 -m tests.blackbox`，整合 lex/run/check 清单、校验、进程捕获与报告，具体字段见 [tests/README.md](../../tests/README.md)。`python -m zzy test examples/features-spec.zzy` 已实现；不要以 test tests/ 混收预期非法程序；下列完整能力按后续阶段补齐。正常 spec、固定输出程序、非法源码分别保存；非法源码不混入会一次性解析的正常 spec 文件。

外部 JSON 清单至少记录：用例 ID、`.zzy` 路径、运行模式、stdin、stdout 期望、stderr 错误码/位置或确定性文字、退出码、超时和工作目录。比较文本只统一 LF/CRLF，不随意 strip 空白或忽略额外输出；JSON 诊断按结构比对，路径采用清单约定的相对定位，避免机器绝对路径影响可移植性。

按路径排序收集；每个外部用例新进程，每个 spec 新执行上下文并隔离导入实例与文件。超时终止用例且记录失败，子进程启动失败也失败；全部失败包括收集错误均计入总数并返回 1。结果报告记录命令、版本、数量和失败详情，禁止把未执行写成通过。

stdout/stderr 并行有界读取，输出超额明确判失败，不只截断后继续比对成功；避免只读一条管道导致另一条写满死锁。超时/取消回收子进程树、句柄和临时目录，确保启动的 GUI/服务不遗留到后续用例。新增收集损坏、持续输出及派生进程场景，不把资源清理与等待遗漏当成功。

运行器默认每例 10 秒、stdout/stderr 各 1 MiB，覆盖值与生效资源配置写入清单。为验证最终 E211 诊断的预留区，相关资源用例显式把外部 stderr 捕获上限设为运行限额加 4 KiB；仍不能因截断而通过。诊断样例以 [diagnostics.md](../language/diagnostics.md) 为依据，容量测试按 [resources.md](../runtime/resources.md)；不得把设计样例当作已采集的真实输出。

## 3. 变形测试：补充固定答案

增加用 ZZY 编写的关系断言，覆盖多个确定性输入：

- 整数数组满足 `array.sum(array.copy(a)) == array.sum(a)`；复制结果与源身份不同，源不变。
- `sum(a)` 对整数排列保持一致；Float 不使用该关系，因为顺序会影响舍入。
- `array.stats(a).count == len(a)`、`.sum == array.sum(a)`；非空时 min/max 与独立逐项参考实现一致。
- 连续结构 with 与逐字段更新得到相同字段值，同时原结构保持旧字段值；不直接以结构 `==` 断言内容。
- 支持类型的 JSON 编解码往返保持标量和容器内容；Array/Map 用逐项参考比较，不用身份 `==` 冒充深比较。
- 同量纲数量在单位换算前后相等，`(distance / duration) * duration == distance`（duration 非零）；另保留 `2::s + 500::ms == 2500::ms` 固定答案。
- 状态机非法事件前后 `.state` 相同；已知事件循环回到原状态，同时核对每步固定 Result 和两实例隔离。
- 查询与分阶段参考筛选/键排序/截取/提取得到相同元素序列；空/同键/desc 与 take=0 另配固定答案和错误清单，不用 Array 身份相等冒充内容比较。
- 对声明为无副作用的示例，带唯一插槽管道和普通调用得到同值；另用计数/输出序列验证有副作用时只求一次。

关系测试仍可能让两个有同样 bug 的函数互相印证，因此同时保留人工固定结果、外部输出清单和独立算法。它是补充，不能替代完整黑盒集。

## 4. 优化和可选扩展

每次优化回放同一批 `.zzy`，比较值、输出、错误码/位置、副作用顺序和别名行为；若选 VM 则 AST/VM 也做此对照。变形用例在未优化和优化执行路径中均运行。

常量折叠加入死分支除零/错类型、超预算大数字/文本的 check 零执行用例；候选失败保留原节点，执行到它时才报原诊断。缓存用例包括字节/条目限额、依赖修改、相同 mtime 不同内容及正在执行版本不被淘汰破坏。

数组校验缓存用例先缓存整数数组，再通过第二个别名将元素替换成 String/Bool，下一次 sum 必须报 `E201`；改变长度、宿主写入、清空或重新填充也必须失效。只有“不变数组快”的用例不够。

Web 若实施，补默认大整数拒绝/显式字符串、只读嵌套模块数据、模块级 Lazy/可变闭包拒绝、独立请求、事务失败回滚、重启持久化和服务仍可用。shape 合约若实施，补“缺字段不等于 Null”、常量默认新建、嵌套路径错误、未知字段拒绝、生成 schema 与实际校验一致。

配额若实施，定义独立于 AST/VM 指令数的语义计步点，比较两引擎的中止位置；宿主调用自带超时。当前这些都是验证设计，不是已通过结果。
