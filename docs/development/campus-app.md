# ZZY 校园任务管家：保存格式与恢复设计

更新：2026-10-15｜应用文件 schema_version：1｜状态：P09 全部已实现并验收，证据见 tests/p09 和开发日志

本文件细化 [roadmap.md](roadmap.md) 的 P09，不替代不少于 200 行 ZZY 应用。业务校验和状态替换由 ZZY 编写，Python 只提供 [stdlib.md](../language/stdlib.md) 的通用 Map/JSON、类型类别和文件接口。

应用的具体菜单、模块职责、启动配置及实际验收映射见 [应用 README](../../apps/zzy-campus/README.md)；入口为 main.zzy；应用测试独立核对 APP-01—03，不以前置语言验证代替应用验收。

## 1. 磁盘格式

保存文件采用 UTF-8 标准 JSON。根对象恰好包含 schema_version、next_id、tasks；每个任务恰好包含 id、title、category、priority、done。不认识的字段/版本拒绝，第一版不猜测迁移，不将 Null 当作缺失。单应用会话管理一个文件，默认不自动保存。

```json
{
  "schema_version": 1,
  "next_id": 3,
  "tasks": [
    {"id": 1, "title": "完成 ZZY 解释器", "category": "课程", "priority": 3, "done": false},
    {"id": 2, "title": "整理演示材料", "category": "课程", "priority": 2, "done": true}
  ]
}
```

| 字段 | 规则 |
|---|---|
| schema_version | 非 Bool 的 Int，当前必须为 1 |
| next_id | Int，1 至 2,147,483,648，且大于所有现有 id；上界值仅表示 ID 已耗尽 |
| tasks | Array，最多 10,000 项；数组顺序就是当前任务顺序，空数组合法 |
| id | Int，1 至 2,147,483,647；全文件唯一；删除任务不回收其 id |
| title | String，1—200 个码点；trim 后至少一个非空白字符，不含 U+0000—U+001F 或 U+007F |
| category | String，1—40 个码点；同样拒绝全空白和上述控制字符 |
| priority | Int，1/2/3，分别为低/中/高；Bool、1.0 和数字字符串都拒绝 |
| done | Bool，只接受 JSON true/false |

标题和分类保存/加载保留原文字，不隐式 trim 或替换字符；交互输入可在用户确认前规范化。应用格式按字段声明顺序输出，但读取不依赖 JSON 对象键顺序。文件最多 4 MiB，深度最多 4 个容器层级；还要满足资源策略中更严格的实际限额。P09 启动配置把 io_payload_bytes 收紧到 4 MiB，不能先无限读取再判断应用文件大小。

ZZY 内部可用固定 Task 结构；磁盘 Map 逐字段验证后新建 Task，不把 data.parse 的任意结果直接当 Task 使用。v1 不保存运行时 Machine、Quantity、Lazy、函数、撤销栈或窗口句柄。此应用已有 Bool 完成状态，不额外保存一份可能与 done 矛盾的状态机状态。

## 2. 完整校验后再替换

加载顺序固定：读文件取得 Result → data.parse → 根类别/键集合 → 版本 → next_id → tasks 类别与数量 → 按数组顺序逐个校验任务 → 检查 next_id 大于所有 id → 一次性提交新应用状态。任一步失败，原内存任务、next_id、撤销栈及当前文件绑定保持不变。

每次使用 data.has/get/keys 或数组下标之前，先用 `data.kind(value)` 检查类别。该接口的闭合集合在 stdlib 定义；Bool 与 Int 不混淆，不靠注解抛出错误进行用户输入校验。应用 validator 显式返回 Result，例如 `(T_T)("tasks[1].priority: 需要 1、2 或 3 的整数")`；路径数组下标从 0 开始。资源超限仍中止执行，不被 validator 吞成格式失败。

必须先检查字段存在，才能 get；用 keys 和字段数检查未知字段。ID 去重用 Map，以已经验证的 Int 转十进制 String 为键，避免对 10,000 项重复两两扫描。检查第一处确定的错误后立即返回，不能留下部分加载结果。

加载成功建立全新状态并清空旧撤销/重做历史，避免撤销到另一文件的数据。若当前有未保存修改，菜单先提供“保存后加载 / 放弃后加载 / 取消”，选择取消不读写文件；保存失败则停止后续加载。

## 3. 保存、首次使用与恢复

保存先校验当前业务状态 → 构造磁盘 Map/Array → stringify 成功 → write_atomic 成功后才标记已保存。任何步骤失败保留当前内存修改与未保存标记，不显示成功；原子替换前失败保留旧目标。保存成功也不清除撤销栈，撤销之后再次视为有未保存修改。

首启展示“新建 / 打开 / 退出”。用户显式新建时建立空状态：next_id=1、tasks=[]，首次保存选择目标路径；遇到任何读取失败不能自动当成空文件。缺文件、权限或编码失败都展示库返回的原因并让用户重试/取消，不解析操作系统错误文字来决定是否覆盖。空文件、坏 JSON、未知版本同样不会被自动修复或覆盖。

加载失败提供“重试 / 选择其他路径 / 保留当前状态”；新会话则返回起始菜单。退出或 EOF 遇到未保存修改不自动写盘：正常交互提示保存/放弃/取消，EOF 无法继续交互时输出未保存提示并结束；Ctrl+C 走运行时取消清理，不把中断当成成功保存。

应用默认单写者使用，不承诺多进程并发编辑合并。write_atomic 防止写一半，不防止另一个进程后来覆盖；第一版指南说明此边界，不新增伪事务或仅凭 mtime 的锁。

## 4. ID、删除与撤销

新任务取 next_id 后递增，超过 id 最大值时返回业务失败，不复用已删除 ID；next_id=2,147,483,648 时禁用新增，读取/删除/保存仍可用。简单撤销使用不可变 Task 替换和数组浅快照；因为 Task v1 字段均为标量，历史不会与当前任务共享可变字段。

撤销/重做记录任务列表，不降低本会话 next_id 高水位，防止撤销新增后又创建出相同 ID。历史最多 100 步，同时受资源预算限制；超出时丢弃最旧的应用快照并提示，这一业务规则与 sketch“不静默丢绘图历史”的扩展规则分别维护。新编辑清除重做分支；成功加载清空全部历史。

未保存状态由当前可保存字段（含 next_id）与最近一次成功加载/保存的值快照比较，比较内容而非 Array 身份；保存文件路径也属于会话状态。实现可先直接比较，10,000 项上限内不引入未经证明的自动缓存。

## 5. 验收场景与任务对应

APP-01：新建 → 新增/编辑/删除/筛选 → 保存 → 重启打开，核对全部字段、顺序和 ID；修改 → 撤销/重做 → 保存后再撤销，核对未保存标记。

APP-02：根为数字/Null、缺/多字段、Bool 冒充 Int、1.0 冒充 Int、重复 ID、next_id 不合法、超长文本/超量任务、未知版本、损坏/缺失/无权限文件；全部不替换当前状态。写入/关闭/替换故障由宿主注入，ZZY 应用验证失败 Result 后旧文件和内存编辑仍在。

APP-03：加载取消、保存失败后加载停止、成功加载清空历史、EOF/中断不自动覆盖、ID 耗尽与历史上限；固定答案与磁盘内容由外部清单验证。应用的通用格式校验可以拆普通 ZZY 模块，但不添加专用宿主“任务管家”接口代写业务。

P09-01 确定 UI/结构并采用此格式，P09-03 实现保存/恢复/历史，P09-05 验证 APP-01—03。源码行数和 Agent 记录仍按 P09-04/05 实际统计。后续格式变更必须另定版本迁移与回退测试，不直接放宽 v1。
