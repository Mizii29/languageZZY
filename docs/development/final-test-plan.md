## 2. 验收目标与默认假设

- **功能与使用者**：面向课程线下验收，验证解释器、所有已实现语言特性、校园应用、Sketch 及给人/Agent 的使用指南；既检查正确结果，也检查错误拒绝与失败后的状态。
- **环境**：正式支持证据先限定 Windows 11 x64、CPython 3.12.14；已有 GUI 环境为 Tk 8.6.12。本轮重新记录实际 OS、Python、Unicode、Tk、字体和 DPI，不将其他组合默认列为已支持。
- **规模**：校园应用覆盖 9999/10000/10001 条、历史 99/100/101 步、4 MiB 文件相邻边界；语言/Sketch 覆盖已有资源边界。单项上限不代表全部最大值可以同时使用。
- **性能**：首先保证同工作量、同答案、同策略；正式采样不与测试并行。建议同机、同配置的成功场景中位数若退化超过 20%，触发复核；这是初始调查阈值，不是语言契约或已确认的性能指标。
- **可靠性**：自动回归零失败、零错误、零跳过；保存/加载失败不丢原状态，取消后不遗留本项目子进程或工作线程。只承诺契约中的原子替换，不扩大为断电持久化或多写者事务。
- **数据与维护**：测试使用合成数据、临时目录和独立演示目录；执行者保存日志，人工结果由实际操作者签记，修复者附回归记录。发现问题登记后处理，不靠改弱期望、放宽限额或删用例通过。

当前验收覆盖单人本地CLI/桌面及已实现P08的Web/数据库/Python嵌入、P10合约，复核默认/shared与失败后恢复；不额外引入新语言能力。下文初始清单的历史数量不作为当前基线，实际收集不得减少旧ID。PNG仍以当前契约为准，正确返回失败Result不能写成“导出成功”。

## 4. 自动测试如何组织

### 4.1 复用与补缺原则

以现有 [test-coverage](test-coverage.md) 的规则编号追踪需求→`.zzy` 样例/独立期望→执行结果，不另建一套语言语义。每条公开规则核对正常、边界、错误三类；重点审查以下组合是否仍有缺口，缺口确认后再补测试：

| 层次 | 必核对的范围 | 实际依据 |
|---|---|---|
| 语言主链 | 词法/注释/Unicode、表达式、类型、数组/结构、控制流、闭包/递归、作用域与求值顺序 | `tests/lex`、`run`、`check`、`p02`、`p03` |
| 特色与库 | Result/Lazy/管道/spec、查询纯性/稳定排序、状态机、Quantity、模块、JSON 与通用 I/O | `tests/p04`、`p05` 及宿主集成测试 |
| CLI 与运行器 | stdout/stderr/退出码/位置、check 零执行、空收集/坏清单/超时/输出超额失败、真实 Ctrl+C 和进程树回收 | `tests/p06`、`test_blackbox_runner`、`test_p06_process` |
| 应用 | CRUD、筛选/统计/TSV、保存/打开/撤销、完整校验后提交、ID 高水位、EOF/取消、4 MiB 与数量边界 | [P09 实际映射](../../tests/p09/README.md)、`tests/p09/coverage.json` |
| Sketch 无窗口 | 几何/填充/图层/文字、对象、历史/回放、图案 Lazy、SVG/项目/函数库、原子失败与配额释放 | `tests/e1`—`e4`、`test_sketch_*` |
| Sketch 窗口 | Tk 主线程、实际事件与像素、回调错误、队列背压、长回调关闭、再次 show、清理 | `tests/gui_sketch.py` |
| P08/P10及P11优化 | 默认/shared HTTP、合约拒绝/隔离、SQLite与嵌入；五项优化的值/诊断/配额/取消及累计退化 | [P10证据](../../tests/p10/README.md)、[P11计划](../runtime/optimization-plan.md)，P11实际映射在实现后建立 |
| 指南与交付 | 已实现示例可运行、Agent 指南与能力标记一致、应用有效源码不少于 200 行 | P06 指南/Agent 测试、`tests.p09.count_lines --check` |

语言语义通过真实 `.zzy` 程序与外部固定期望验证；Python 负责通用驱动、生命周期断言、故障注入和答案比对，不替代 ZZY 应用业务。不得把全部 `tests/` 直接交给 `zzy test`：其中有故意非法的源码，应使用统一外部运行器和独立正常 spec。

### 4.2 本地复现命令

以下为待执行命令，均从仓库根目录运行。每条命令结束立即检查退出码，非零时记录并停止该阶段；后续成功命令不能覆盖前面的失败。日期、短 SHA 与 attempt 按实际候选版本填写。

```powershell
$ZzyPython = (Resolve-Path ./.venv/Scripts/python.exe).Path
$FinalEvidence = "dist/final-verification/2026-10-20-b598043-attempt-01"
New-Item -ItemType Directory -Path $FinalEvidence -ErrorAction Stop
& $ZzyPython -X utf8 -c "import sys; assert sys.version_info[:3] == (3,12,14); print(sys.version)"
git status --short
git rev-parse HEAD
& $ZzyPython -X utf8 -m tests --report "$FinalEvidence/all-tests.json"
```

一键回归已包含语言黑盒和应用专项；只有诊断问题或需要逐用例 JSON 时才额外运行下面的独立入口，其结果不与全量数相加。

```powershell
& $ZzyPython -X utf8 -m tests.blackbox --report "$FinalEvidence/blackbox.json"
& $ZzyPython -X utf8 -m tests.p09.count_lines --check
& $ZzyPython -X utf8 -m tests.gui_sketch --report "$FinalEvidence/gui.json"
```

GUI 必须有真实 Windows 桌面、可用 Tk，缺环境记为未执行/环境失败，不能 skip 后称整体验收通过。当前 GUI 套件含 Windows 专用像素检查，不能直接作为 Linux GUI 门禁。人工操作也不能以这些自动事件探针代替。

### 4.3 安装与离线验收

1. 准备带 CPython 3.12.14/Tk 的独立验收环境及已有 pip/setuptools（`setuptools>=68`）；记录完整工具版本。先备齐构建工具，再断开下载来源。CI 能联网准备环境不等于产品已通过离线安装。
2. 复用 [安装驱动](../../tests/e4/install.py)：`python -X utf8 tests/e4/install.py --installer <已有pip和setuptools的Python绝对路径>`。尖括号表示需替换的参数，不是可原样执行的 PowerShell 命令。
3. 该驱动硬编码写入 `tests/e4/results/installed.json`，会安装到新 venv **及调用它的当前 Python**，并执行真实 GUI；只在独立验收副本/专用 venv 使用，先保留旧报告，完成后把新报告、wheel 与哈希归档到本次证据目录。不要误将其当作通用无窗口 CI 安装脚本。
4. 核对新包来源、新旧源码一致、`-I` 且 cwd 在源码目录之外；中文/空格路径中实际执行 check、headless、GUI、关窗保存、另一进程加载/undo/函数库复用。
5. 最终交付包还应携带 `apps/`、`examples/`、文档和测试资料；wheel 只打包 `zzy*`，单独 wheel 不等于八项作业材料齐备。校园应用须在离开源码目录后带 `limits.json` 再做保存→退出→重启恢复。

`tests.e4.accept` 是 E4 历史证据汇总器：使用固定路径、源码哈希及既有报告，不是重新执行测试。不要用它读取旧文件来证明新候选版本或新 CI 已通过；本轮报告另建索引，关联本次实际执行产物。

M14 的确定性长回调/队列失败由自动用例负责精确断言，人工补充实际关窗与操作感受。M17 的额外 DPI 无设备条件时明确标“该组合未验证”；正式主环境的可操作性仍必须通过。真实 ACL 拒绝可在可恢复的独立测试目录补测；现有故障注入证据不能写成真实 ACL 测试。

## 6. 性能、容量与稳定性

先跑功能等价，再做正式计时；输出目录使用新的 attempt，B01—B09 驱动要求 `--output` 指向尚不存在的目录。下列目录是 `$FinalEvidence` 的新子目录/文件，不要提前创建 `core-equivalence` 或 `core-performance`：

```powershell
& $ZzyPython -X utf8 -m benchmarks.run --verify-only --output "$FinalEvidence/core-equivalence"
& $ZzyPython -X utf8 -m benchmarks.run --output "$FinalEvidence/core-performance"
& $ZzyPython -X utf8 -m benchmarks.sketch.run --repeats 3 --output "$FinalEvidence/sketch-generation.json"
& $ZzyPython -X utf8 -m benchmarks.sketch.render --all --repeats 3 --output "$FinalEvidence/sketch-render.json"
& $ZzyPython -X utf8 -m benchmarks.sketch.seek --all --repeats 3 --output "$FinalEvidence/sketch-seek.json"
```

核心基准沿用清单固定规模、种子、3 次预热、15 个样本及 30 秒子进程限额；Sketch 沿用三类场景、三档规模、每档 3 次新进程。记录 CLI 总耗时及内部阶段，不能把嵌套阶段重复相加，不能把 ZZY 与 Python 的不同工作量作速度比。

核心正式基准与4.2节功能测试的退出口径须分开：现有[性能报告](../runtime/performance-report.md)已记录多项大规模30秒超时及`not_measured`，`benchmarks.run`只要出现失败记录就退出1。复现时如实保留非零码，先审查完整原始数据与预先确定的失败类别，再决定下一项测量；不得把它改写成“全部工作量通过”。可用`python -X utf8 -m benchmarks.audit <本次core-performance目录>`核对证据完整性；audit成功仍需看`all_workloads_passed`，证据完整与工作量全部成功是两个结论。固定小规模`--verify-only`应全部正确，新增错误答案/正常规模失败必须处理。

已有 Sketch GUI/Replay 大规模场景会触发默认资源拒绝。驱动允许记录 `resource_failure` 并完成采集，因此退出 0 只说明采集协议完成；必须另审 `status` 分布和预期矩阵。只有 `ok` 样本参与耗时统计，资源拒绝、错误、超时分别列出；正常小规模新增拒绝也算待处理退化。

建议增加 20 次“打开→编辑→保存→关闭→重启加载”的稳定性循环，以及约 10 分钟绘图/回放/窗口开关探索。核对每轮文件与状态、进程/线程清理和资源计数是否持续增长；这些是建议新增的执行项目，当前没有相应通过证据。逻辑配额不等于 RSS 硬上限，不要求 CPython 进程退出前把所有 RSS 还给 OS。

云端共享机器仅用于正确性和趋势观察。正式对照须同机同配置，保存 CPU/内存/电源模式/系统负载和原始样本；出现超过建议阈值的退化时复跑对照并解释，不预设 ZZY 必须比 Python 快。

## 7. 缺陷处理、证据和最终放行

缺陷建议分级：B0 为数据丢失、错误答案、崩溃/死锁、无法安装启动或关键测试漏收；B1 为主要功能/交互失败、取消清理失败或文档命令不能复现；B2 为不阻断使用的表现/文字问题。B0/B1 修复并复验后放行，B2 明确修复或在已知问题中记录影响。

每次尝试使用独立目录，保存环境、完整命令、起止时间、commit/差异、源码与夹具哈希、退出码、汇总 JSON、双流日志、wheel SHA-256、人工记录和性能原始样本。失败报告保留；修复后新的完整重跑不能用“旧成功项加一个专项成功”拼成全量通过。最终报告应列出各阶段状态、缺陷关闭情况和剩余未验证范围。

CI回归日志按 [日志配置](../runtime/logging.md) 轮转并淘汰旧片段；归档时记录report/log中的older_logs_discarded。若为true，说明仅保留最近部分，需要全程日志时应在执行前审查并提高日志限额，或另在有容量管理的外部采集器保存；完整测试计数/退出码仍由JSON门禁验证。

本轮放行必须同时满足：

1. 自动入口退出 0，`collected = tests_run > 0`，`passed = true`，failures/errors/skipped/expected_failures 全零；用例集合与范围基线匹配，数量减少有明确审查结论。
2. 实际候选版本的真实 GUI、新环境安装、中文/空格路径、应用重启与绘图往返通过；人工 M01—M18 的主环境必测内容均有真实记录。
3. 性能正确性通过，成功/资源拒绝/错误/超时分类齐全，明显退化已处理或准确说明；没有悬而未决的 B0/B1。
4. 按 [作业原文](../requirement.md) 核对语法、解释器、黑盒、性能报告、指南、应用及 Agent 记录、Git 历史、PPT 八项材料；有效应用行数与当前源码匹配，现场演示可复现。
5. 代码、wheel、报告和最终交付物可追溯到同一候选版本；`todo.md`、开发记录及能力说明准确；之后才按实际完成范围更新 P12。

其他 OS/Python、所有字体/DPI、断电、多写者事务、所有最大容量组合及所有阻塞宿主调用取消时序，除非本轮专门执行，否则继续列为未验证。最终交付索引与 PPT 的实际制作仍按 P12 推进，本计划不代替它们。

## 8. 设计取舍

| 决定 | 其他方案 | 采用原因 |
|---|---|---|
| 复用现有回归，先审覆盖缺口 | 重写一套测试框架 | 现有外部期望、进程治理和故障注入已可用，集中精力验证最终组合 |

| 正式性能独占本机 | PR 云端速度阈值直接放行 | 控制环境噪声，保留可解释的配对结果 |
