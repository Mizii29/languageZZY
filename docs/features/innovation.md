## 1. 当前语言特色

这些是核心设计，不依赖 Web；拼写的辨识度与运行时机制分别说明。

### 1.1 关键字穿括号，声明先说 yes/no

`(zyes)` 表示“这个名字以后可以换值”，`(zno)` 表示“这个名字不能重新绑定”。例如计数器用 `(zyes)`，固定的作者名字用 `(zno)`。`(addnew)` 像“新增一个功能”，三个分支关键字像连续问问题。

```text
(zno) author := "赵梓伊";
(zyes) count := 0;
count <- count + 1;
```

这让关键字在代码里更醒目，也能直接表达修改意图。要注意 `(zno)` 不是深度冻结：它指向的数组仍可能被修改。括号主要带来辨识度；解释器只在读源码时识别它，不能把长关键字说成加速技术。

**安排：** P00 定规则，P01 开始实现。**演示：** 修改计数器成功，重新绑定 author 得到清楚的错误。

### 1.2 `[OoO]`：看到惊讶脸，就做字符串转义

ZZY 不用传统的反斜杠转义，改成 `[OoO]n` 换行、`[OoO]q` 写双引号。`(raw)` 则表示原样文字，适合路径等内容；字符串外的数组符号和 URL 中的 `/` 不受影响。

```text
io.print("你好[OoO]nZZY！");
```

关键的实现选择是“读一次，转换一次”：加载时把标记变成真正的换行，打印时直接使用最终字符串。这样能保留俏皮风格，又避免每次循环都辨认颜文字。更长的源码仍有扫描成本，实际大小需要测量。

**安排：** P01。**演示：** 普通字符串换行，原样字符串保留标记，未知转义给出位置。

### 1.3 笑脸和哭脸：把成功、失败都当成数据

`(^_^)(42)` 像一个装着结果的笑脸信封，`(T_T)("输入无效")` 像一个装着错误说明的哭脸信封。程序通过 `(?_?)` 打开对应信封，而不是把错误偷偷变成 0 或空字符串。

输入校验、文件处理和 API 业务都可以统一使用 Result。返回 Result 的函数还能用后缀 `?`：成功继续，失败直接把同一失败返回给调用者。它减少重复的错误分支代码，但不代表计算自动更快。

**安排：** P04。**演示：** 同一个函数对正常输入返回笑脸，对非法输入返回哭脸；验证失败后没有执行剩余副作用。

### 1.4 `zzz` 打个盹：没用到就先不算

`(zzz)(array.sum(scores))` 像先开一张取餐单，暂时不做统计。第一次 `wake` 才计算，并把结果存起来；后续唤醒同一个对象直接读缓存。

如果计算很贵、结果会重复使用，这可能省工作；如果只算一次很便宜的加法，保存状态反而可能更慢。它不是后台线程，也不自动追踪数据变化：scores 更新后，旧的 Lazy 仍保留已经算出的结果，程序需要创建新对象。

**安排：** P04，P07 测量。**演示：** 用计数验证只计算一次，再展示缓存不会自动刷新。

### 1.5 波浪管道：数据顺着步骤游过去

`scores ~> array.sum(@)` 可以读成“把 scores 送去求和”，`@` 指明结果放进哪个参数位置。长处理过程因此可以逐段写，不用层层嵌套函数。

这里的实现亮点是严格保证左侧只执行一次。例如左侧读取输入，不能因为处理插槽而重复询问用户。管道本身主要改善阅读；以后可以提供明确的批量处理接口，但不能随意合并带副作用的回调，改变输出或错误顺序。

**安排：** P04。**演示：** 筛选后求和，并用一次输入或计数验证求值次数。

## 2. 用户已选的 A/C/D/E

A/C/D 纳入 P04，E 在 P05/P06 后按 E1—E4 完成。完整规则仍由三个专题契约维护。

### 2.1 A：集合查询，也能封装成小库

`tasks ?> {(keep): (not) @.done; (order): @.priority (desc); (take): 2; (yield): @.title;}` 将挑选任务直接变成语言规则。输入求值一次，按固定阶段执行，键求值一次，两个方向都保持相同键的原顺序；查询返回新 Array，条目不能偷偷写状态或执行 I/O。

区别于把关键字换个名字，这里增加 QueryExpr、当前项作用域、纯绑定检查和确定的查询执行计划。可封装为普通具名函数，通过现有模块导出给其他 ZZY 程序使用；不额外发明 query.compile 或自动刷新。

**安排：** 已纳入 P04-08；P05 补白名单库和模块封装，P07 测扫描/准备/执行。**证据：** QUERY-01/02/03、外部固定答案、错误/求值顺序、稳定 desc、Quantity 键与遮蔽拒绝；等价 Python 对照计入快照与校验。完整规则见 [query.md](query.md)。新增场景中仅 E 画笔工具已采用，其他兴趣主题未纳入。

### 2.2 C：状态机，把合法流程直接写出来

`todo -- "start" --> doing;` 不是把 if 换个名字，而是定义一个完整的允许变化表。`progress << "start"` 由语言查询当前状态、验证事件并返回 Result；不允许的事件保持原状态。重复源状态/事件在准备阶段拒绝。

这适合任务、订单、游戏角色。每个实例独立，别名共享；状态只通过发送事件改变。第一版没有动作回调或并发队列，转移表可准备一次复用。业务历史须保存状态快照，不能浅拷贝一个仍会变化的实例引用。

**安排：** 已纳入 P04-06，不再是 P10 待选项。**证据：** 正常流程、非法跳转不修改、重复边、只读 state、独立实例/别名/冻结；P07 对照相同流程校验的 Python 实现。完整语法见 [machine-units.md](machine-units.md)。

### 2.3 D：带单位数值，把“秒和米能否相加”交给语言

`2::s + 500::ms` 精确等于 `2500::ms`，而 `2::s + 1::m` 报量纲错误。`10::m / 2::s` 得到速度。数量保存约分有理数和量纲，不是打印时才拼单位文字；精确数量小数与普通 Float 有各自明确规则。

第一版固定时间/长度/无量纲单位，不加入温度、货币或用户定义单位。有理数约分可能更慢，需测操作数位数和资源上限，不能为了展示创新保证速度收益。库仅增加精确 make/format，JSON 默认拒绝数量，避免偷偷丢单位或精度。

**安排：** 已纳入 P04-07，库在 P05。**证据：** 时间/长度换算、量纲不符、速度相乘还原距离、精确小数、零除、无量纲仍为 Quantity、大数与显示；Python 对照也使用等价有理数规则。A 在 v0.6 已采用，B 未采纳，不生成自动刷新语法示例。

### 2.4 E：梓伊小画室，画好就能封装复用

sketch 提供类似 turtle 的移动、转向、抬落笔、路径和填充，补齐多画笔/图层、鼠标工具、分组撤销、确定回放、SVG/项目文件与 ZZY 图案函数库。亮点是完整组合与语言协作，不宣称 turtle 没有撤销，也不只给 Python API 换名字。

绘图先成为统一文档；撤销恢复位置/朝向/样式，回放读取已发生的绘图记录，不重跑随机/输入/回调。capture 保存不可变图案，stamp 做缩放旋转，导出器生成普通 Result 函数及私有 Lazy 缓存，再用同一 Lexer/Parser/Resolver 检查。窗口、回调、背景和画笔句柄不装进图案库。

A 筛选普通图层快照，C 管理工具/播放状态，D 表达计时间隔；不增加核心 Token、角度/像素/红温单位或查询纯函数。可爱提示如“画笔摸鱼中”“这一笔先回去进修”保留正式错误/位置。headless 模型与 Tk 分离，增量历史、共享路径块、批量接口和有界队列都有性能/清理验证。

**安排：** E1—E4 已按顺序实施，最终验收见 [tests/e4](../../tests/e4/README.md)；PNG 独立标注不可用。**证据：** SKETCH-01—06、几何固定答案、失败无部分写入、撤销/项目往返、跨文件图案库调用、关窗与溢出清理、分阶段公平测量。完整接口见 [sketch.md](sketch.md)；其他新场景、动漫/游戏主题未采用。

## 3. 核心工程设计与验证

槽位、宿主库、能力清单与测试是实施方法或验证措施，先实现正确基线，再证明效果。

### 3.1 固定结构：既是业务表格，也是编号抽屉

`(shape) Task` 规定任务只能有哪些字段，就像一张栏目固定的表格。字段固定后，解释器可提前知道 done 在第几格，减少反复按名字寻找；访问动态对象时仍要检查实际结构。

`task (with) {done: (true)}` 会创建修改后的新结构，原结构保留。这适合应用自己维护修改前后的记录。它是浅层复制，嵌套数组可能共享，不能声称语言已经自动提供完整撤销系统。

局部变量也提前安排编号槽位；闭包与 Lazy 捕获可变绑定共享 Cell，每轮循环另建绑定，不能简单复制值或共用最后一轮槽位。结构默认值若是外部数组名字仍共享，只有新建表达式才创建新对象。收益来自定位方式，不来自字段拼写。

**安排：** P02/P03。**演示：** 结构更新和闭包正确性；P07 对照变量访问的耗时。

### 3.2 一次搬整箱：宿主批量库与 `array.stats`

用 ZZY 循环逐项求和，解释器每次都要处理读取、加法和赋值。`array.sum(numbers)` 一次进入 Python 宿主函数，完成同样的工作，减少逐条解释的往返。

`array.stats` 一次遍历求 count/sum/min/max，像一次拿齐统计数据。当前 sum/stats 只接受 Int；空统计 count/sum=0，min/max=Null，sorted 返回新数组。一遍 Python 循环是否快过多次宿主函数仍待测，不能为了快省类型检查。

自己用 ZZY 写库主要方便复用；用 Python 包装批量操作才可能减少 ZZY 执行开销。两者不等价，批量库也有调用和转换成本，需要与 Python 等价调用公平比较。

**安排：** P05/P07。**演示：** 手写循环与库得到同一结果，再展示真实测量数据。

### 3.3 变形关系帮助找“看起来正确”的 bug

除了“输入 [1,2,3] 得到 6”，还检查一组应该成立的关系：整数数组复制后总和不变，stats 的 count 等于 len，JSON 往返保持内容，管道与普通调用保持同样值及求值次数。一个规则能覆盖多个输入，对优化引入的引用/缓存错误尤其有用。

```text
(spec) "整数统计与复制的一致性" {
    (zno) values := [3, -2, 5];
    (zno) copied := array.copy(values);
    (zno) report := array.stats(values);
    (o_o) copied != values;
    (o_o) array.sum(copied) == 6;
    (o_o) report.count == len(values);
    (o_o) report.sum == array.sum(values);
    copied[0] <- 99;
    (o_o) values[0] == 3;
}
```

这是待实现的 ZZY 用例。容器 `==` 比身份，JSON 往返须逐项比较；整数排列关系不能用于 Float；两个有相同 bug 的函数可能一起“通过”，所以必须结合人工固定答案和独立算法。

**安排：** P06-01已有基础；P10-08完整扩展延期，P11仅补所选优化必需的关系/参考路径对照，不因此完成P10-08。**证据：** 固定种子/输入、关系用例、适用的故障注入及真实 CLI 结果。它是验证方法，不代替完整黑盒集，也不自动证明解释器全部正确。

### 3.4 能力清单帮助 Agent 使用真实接口

从发布版本的语法功能表和宿主注册表生成带语言版本的能力清单，列出已启用关键字、库函数签名、错误码与可运行例子。Agent 先读清单，再生成代码；未实现的 web/num 不会因为在路线图里出现就被误用。

一份声明生成接口速查与机器可读清单；示例只有被真实解释器跑过才进入“已验证”列表，不能由生成器自动填通过。JSON 诊断将错误码、原文 span 和规则链接交给 Agent，再由测试判断修复。它减少文档与运行时接口漂移，不自动修程序。

**安排：** P06-04，发布新接口时更新。**证据：** 注册表/清单/指南的接口集合一致，Agent 仅凭指南完成实际练习；未知能力产生明确诊断。

## 4. 可选后续与条件优化

P08 互联在完整 CLI 应用之后；P10 候选按依赖、热点和时间选择，不作为已选扩展或必需交付。

### 4.1 用标准接口说话：网页和 Python 都能使用 ZZY

可以把 ZZY 看成负责业务的厨房，Python Web 适配层是接待员。网页通过 HTTP 送来参数，ZZY 处理任务，再用标准 JSON 返回；前端不必学习 ZZY 的关键字和颜文字。

还可以提供 Python 嵌入接口，让 Python 项目加载 ZZY 模块并调用导出函数。跨语言先采用 HTTP/JSON，本地采用明确的数据转换和函数接口，不急着支持任意宿主对象。

程序启动时准备，请求只传数据；每请求独立上下文，共享模块和捕获环境递归冻结，模块级 Lazy/可变闭包不能跨请求共享。数据库负责业务状态，JSON 不使用 `[OoO]` 转义。大整数必须显式 String 字段协议，不能默默改变类型。

**安排：** 核心 CLI 应用 P09 完成后可选 P08。**演示：** 网页新增任务，ZZY 校验处理并持久化；Python 示例调用导出函数。

### 4.2 给数组盖“这个版本已检查”印章

重复统计一个未修改数组时，每次都重新确认“全部是 Int”可能浪费检查。数组保存 content_version，通过检查后记下版本；下次版本相同就复用类型判定。就像盖章只对当前一箱货有效，换了一件货就要重检。

关键边界：元素替换也更新版本，不能只跟踪长度；通过别名、push/pop、宿主接口修改同样失效。缓存只保存成功类型判定，包含对象、内容版本和判定规则版本；sum/stats 仍重新计算，不把旧和当新答案。第一版不缓存含嵌套可变对象的深层类型，也不缓存失败判定。

验证例：第一次检查 `[1, 2, 3]`；第二次不修改可命中；另一个别名将第一个元素改成 String，第三次必须报类型错误。所有写入口统一更新版本才允许打开优化。缓存放在数组自己的有界元数据中，数组回收时同时释放。

**安排：** P02/P05已建版本入口，P10-07本轮延期，理由见第6节；P11-05只分离sum/stats工作，不引入此缓存。**若重启需有证据：** 小/中/大数组、重复读取、每次修改对照，记录校验次数、命中率、总时间和写入开销。它不将 O(n) 求和变成 O(1)，没有测量时不宣称加速。

### 4.3 一份 shape，多处对齐：结构驱动接口合约

2026-10-29已明确选择P10-01及对应P10-06。实际入口与限制见[Web契约](../runtime/web.md)，演示与证据见[tests/p10](../../tests/p10/README.md)，最终状态看todo；本版不生成TypeScript。

这是 Web 实施后的优先深入扩展候选。假设新增任务需要 title 字符串，后端用 `(shape)` 写清楚后，工具同时生成请求校验、JSON 字段转换规则和接口说明，之后可继续生成前端 TypeScript 类型。

它像只填写一份标准表格，就给前后端各打印一份说明。字段拼错或类型不对时，先给出清楚的输入错误；开发者不必在三处手工维护同一套字段。

第一版生成范围明确：注解为 Int/Float/String/Bool/Null、Array/Map 或无环嵌套 shape；Array 没有元素注解，schema 不能编造“整数数组”。拒绝未注解字段、Function/Result/Lazy/Range/Machine/Quantity、递归结构与非标量常量默认，普通运行时结构仍可使用这些字段。缺字段只有带允许默认值时才可省略；显式 Null 仅满足 Null 类型，不能当成缺字段。默认不执行任意表达式，未知字段拒绝；HTTP Int 采用安全整数范围。

从同一中间结构生成校验器、字段转换和 OpenAPI 3.1 schema，后续再生成 TypeScript。OpenAPI 的 default 只描述默认，工具仍须显式实现缺失字段填充，不假定第三方验证器会自动填值。嵌套失败给出如 `body.task.title` 的路径。生成器须与实际校验一起测试，schema 验证结果不能与后端相反。[OpenAPI 3.1.1 schema 说明](https://spec.openapis.org/oas/v3.1.1.html#schema-object)

**安排：** P10-01/06已验收；实现范围以Web契约及todo为准。**演示：** 改一个字段，校验和接口说明同时更新；错误请求在进入业务前被拒绝。

### 4.4 给请求一张计步卡：执行配额

为每请求记录语义步数、调用深度和期限，超限停止请求。计步点由语言执行事件定义，如表达式入口/循环条件/函数进入，并记录版本；不能将 AST 节点数与 VM 指令数混用，让同一代码切引擎就获得不同配额。超额中止释放遍历计数和 Lazy 求值中状态，不永久缓存取消诊断。

它的价值是让后端更容易管理，不是让一次加法更快。步数检查不能打断已经进入的数据库或宿主函数，所以这些工具还要自己的超时；要求强制终止时可采用独立进程。

**安排：** P10-02本轮延期，保留设计；收益、现有控制与新增成本的取舍见第6节。**未来演示：** 超额请求被终止，之后的正常请求仍可执行；当前不宣称语义计步或强制宿主中止已实现。

### 4.5 先看清类型再走快路：可选专用指令

如果测量发现解释器大部分时间花在“这是什么操作、是什么类型”的判断，可以考虑字节码或专用操作。例如确认两个值都是 ZZY Int 后，执行整数加法路径；已知结构布局后，直接按字段编号读取。

“守卫”就是进入快路前的检查。条件不满足时走通用处理，或按原规则报告错误，不能漏掉类型约束，也不能把任意精度整数改成会溢出的机器整数。这不等于已经实现 JIT，Python 写的 VM 也不保证更快。

**安排：** P10-03完整字节码/专用指令候选延期；用户选定的小整数守卫范围单独进入P11-04，详见[优化计划](../runtime/optimization-plan.md)。**未来演示：** 快路与通用路径结果、错误一致，再比较对应基准；不重复勾选P10-03。

### 4.6 更远的两项想法：纯函数缓存和版本切换

**纯函数缓存**像保存一道只依赖题目本身的答案：相同参数直接取结果。但读时间、访问数据库、打印、修改外部变量都会改变问题，不能随便缓存。第一版若尝试，应限制在标量输入输出、能确认没有外部读写的函数；它和显式的 Lazy 是两种机制。

**模块版本切换**像新菜谱先试做成功再交给厨房，正在做的旧订单继续使用旧菜谱。新代码出错就保持旧版本；程序和依赖要作为一致快照切换，数据库变更仍需另行处理。

两者都有较高实现成本，先保留为后续实验。可以讲设计边界，只有实际完成并验证后才能在成果中写“已实现”。

**安排：** P10 可选，优先级低于完整应用与作业交付。
