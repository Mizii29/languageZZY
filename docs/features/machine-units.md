## 1. C：用箭头画出允许发生的状态变化

例如任务只能从“待做”开始，到“进行中”，再到“完成”；完成后允许重新打开。直接把规则写成图：

```text
(machine) Progress {
    todo -- "start" --> doing;
    doing -- "finish" --> done;
    done -- "reopen" --> todo;
}

(zno) progress := Progress("todo");
(zno) started := progress << "start";
(o_o) started == (^_^)("doing");
(o_o) progress.state == "doing";

(zno) denied := progress << "reopen";
(o_o) denied == (T_T)("invalid transition: doing -- reopen");
(o_o) progress.state == "doing"; zzysay: 失败不改状态
```

一条箭头读作：“在左边这个状态，收到中间这个事件，就进入右边那个状态。”`<<` 读作“给这个对象发送事件”。它不是整数移位，也不是后台消息队列。

### 1.1 定义、类型与构造

- `(machine) Name { ... }` 只允许文件顶层，至少一条边，不加末尾分号。边为 `IDENT -- STRING --> IDENT;`，事件用普通双引号字符串，解码后不得为空。
- 状态集合就是所有边端点的并集，状态名称采用标识符原文拼写、区分大小写。第一版不另设孤立状态声明。状态标签属于定义内部，不声明源码变量，不查找外层同名变量；仍不能使用保留名称作为标签。
- 同一 `(源状态, 解码后的事件)` 只能有一条边，重复即 `E305`，即使目标相同也拒绝；不同源状态可使用相同事件。自环、环和不可达状态允许；不推断隐含边。
- 定义在 Resolver 阶段登记不可重新绑定的名字，与函数/结构共享声明命名空间；重复名字为 `E301`。边表仅由标签和常量组成，准备阶段可构建只读转移表，`check` 不创建实例或执行转换。
- `Name(initial)` 恰好接受一个 String，必须是该定义中的状态名称；参数类型/数量错误为 `E201/E202`，未知初始状态为 `E212`。每次成功构造创建独立实例，没有自动选初始状态。
- `(Machine)` 注解接受任意状态机实例；`Progress` 注解仅接受该定义创建的实例，按定义身份判断，不因图相同就兼容。定义对象不是实例，不能满足 `(Machine)` 注解。

### 1.2 发送事件和副作用

1. `left << right` 从左到右各求值一次。求值失败即停止；然后检查左边为 Machine、右边为 String，错误为 `E201`。
2. 检查实例可写性；冻结实例发送任何事件均为 `E203`。`(zno)` 只限制名字重新绑定，不冻结实例。
3. 查当前状态对应的事件。找到边，先准备成功 Result，再将状态改为目标，返回 `(^_^)(目标状态字符串)`；分配失败不能留下已经修改的状态。
4. 找不到边，包括未声明的事件或空字符串，返回 `(T_T)("invalid transition: " + 当前状态 + " -- " + 事件)`，不修改状态。消息中的事件使用原字符串，不额外解释转义。

`instance.state` 是只读 String 属性，其他字段访问报 `E204`；对 state 赋值报 `E203`，也不能通过 `(with)` 绕过转换规则。两个名字引用同一实例时共享状态；两个构造调用相互独立。实例/定义的相等为身份相等，成功 Result 比较载荷内容。

`<<` 优先级低于 `(with)` 与逻辑运算，高于 `~>`。第一版同一层最多一次发送，`a << b << c` 为 `E103`；发送返回的是 Result，继续发事件要另写语句。要使用失败传播，写 `(progress << "finish")?`，并遵守具名 Result 函数的既有上下文限制。

第一版不加守卫表达式、回调、进入/退出动作、事件排队、并发或事务回滚。一次发送仅执行表查找和状态写入；之前求实参产生的 I/O 不因失败而回滚。它的价值是让合法流程成为语言规则，不以“比 if 一定快”为卖点。

### 1.3 模块、保存和撤销

状态机定义可以由模块导出；实例归当前 ExecutionContext，不能缓存或共享一个可变实例给所有请求。冻结规则也覆盖结构、Array/Map 中嵌套的状态机实例。

JSON 不自动序列化 Machine 或定义。应用显式保存 `progress.state` 字符串，并在加载时经过构造器验证；应用若需要 Result 型加载失败，应先对持久化状态进行自身的允许集合校验，不假设致命构造错误可捕获。

简单撤销可保存旧状态字符串，恢复时创建新实例并替换应用记录。历史中直接保存同一可变 Machine 引用会随后续发送改变，不能声称浅拷贝数组就保存了历史状态；原有纯标量 Task 的 `(with)` 撤销方案仍适用。

## 2. D：数字自己带着单位

```text
(zno) duration: (Quantity) := 2::s + 500::ms;
(o_o) duration == 2500::ms;
io.print(unit.format(duration, "ms")); zzysay: 预期 2500::ms

(zno) distance := 10::m;
(zno) speed := distance / 2::s;
(o_o) speed * 2::s == distance;
(o_o) 0.1::s + 0.2::s == 0.3::s;
```

普通数字无法看出“2”代表秒还是米；Quantity 把数值与量纲一起保存。秒与毫秒可换算后相加，秒与米相加则报 `E213`。速度是长度除以时间得到的量纲，不需要用户自己记换算系数。

### 2.1 第一版固定单位

| 量纲 | 支持单位 | 相对于基础单位的精确倍率 |
|---|---|---|
| 时间 T | `ms`、`s`、`min`、`h` | `1/1000`、`1`、`60`、`3600` 秒 |
| 长度 L | `mm`、`cm`、`m`、`km` | `1/1000`、`1/100`、`1`、`1000` 米 |
| 无量纲 | `one` | `1` |

单位名称区分大小写，不支持别名、复数、自定义单位、温度、日期或货币。单位表固定且有版本；`m`、`min` 等仍是普通标识符，不全局保留为关键字。

字面形式为 `(INTEGER | FLOAT) :: IDENT`，允许词项之间的空白/注释；负号在外层，例如 `-2::s`。单位位置的 IDENT 只查固定单位表，不查变量，未知单位在准备阶段报 `E306`。`amount::s` 不合法；普通表达式转为 Quantity 使用 `unit.make(amount, "s")`。

Lexer 只切出数字、已有 `::` 和标识符，数字 Token 保留原文；Parser 据数字后的 `::` 选择数量字面节点，据限定名字后的 `::{` 选择结构构造。数值在准备阶段只转换一次，不让扫描器为了认单位去解析整个表达式。

### 2.2 精确表示和运算

Quantity 是不可变的独立值类型，不是给 Int/Float 附加打印后缀。保存基础单位数值的约分有理数 `分子/正分母` 和量纲向量 `(L指数, T指数)`；无需保存可变的展示单位。宿主基线可用标准库 `fractions.Fraction`，乘除后约分。

Quantity 字面量中的十进制小数按源码文本精确构造，例如 `0.1::s` 为 `1/10` 秒；普通 `0.1` 仍是 Float。数字 Token 的 FLOAT 是词法外形，不强迫 Quantity 字面量先转为二进制 Float；普通 Float 字面节点仍必须有限。

| 操作 | 规则 |
|---|---|
| `+ -`、`< <= > >=` | 两个 Quantity 的量纲必须相同，不同报 `E213`；先按基础单位比较或计算 |
| 一元 `+ -` | 返回同量纲 Quantity |
| `Quantity * Quantity` | 数值相乘，量纲指数相加 |
| `Quantity / Quantity` | 数值相除，量纲指数相减，零除数 `E205` |
| 与标量 `* /` | Int 或有限 Float 可在任一侧参与乘除；Bool 拒绝，返回 Quantity；标量视为无量纲 |
| `== !=` | 同量纲、同精确数值即相等；不同量纲为不相等；Quantity 不与 Int/Float 隐式相等 |
| `// %`、区间、数组下标 | 不接受 Quantity，沿用 `E201` |

Int 标量精确提升；来自运行时的 Float 用其实际二进制数值转有理数，不从显示文字猜原来的小数。因此 `unit.make(0.1, "s")` 不保证等于精确字面 `0.1::s`。禁止静默地将已算出的 Float 当精确十进制数。

两个同量纲数量相除得到无量纲 Quantity，例如 `1::m / 50::cm == 2::one`，不偷偷退化为 Int/Float。`(Quantity)` 注解只检查外层值，不能静态证明所有量纲正确；变量参与的运算仍需运行时检查。数量不支持常量匹配模式，第一版可用条件相等或末尾 `_`。

有理数使用任意精度整数，精确不等于免费。需限制输入数字长度、分子/分母位数、量纲指数及中间运算；先检查预计分配规模再计算，超限为 `E211`，不得为了速度悄悄改为 Float。执行限额与普通大 Int 共用明确资源策略。

乘除可先交叉约分再相乘，减少中间整数位数，仍得到同一规范有理数；大小比较的临时交叉乘积也纳入资源预算。用等价 Fraction 路径对照固定答案与位数增长，不能只检查最终已约分结果而忽略中间分配。

### 2.3 显示、转换与 JSON

`unit.format(q, "ms")` 仅返回 String，不改变 q。目标必须是固定单位、量纲必须匹配；单位名称未知为 `E306`，量纲不符为 `E213`。数值若整数用整数文字，否则显示约分的 `分子/分母`，例如 `unit.format(1::s / 3, "ms")` 为 `"1000/3::ms"`，没有不确定的舍入。

`str(q)` 和 `io.print(q)` 使用基础单位规范格式：整数或约分有理数，随后 `::` 和量纲标签。维度顺序固定 L 后 T；非零指数记为 `m^k`、`s^k`，以 `*` 连接，指数 1 不写 `^1`，指数 0 省略，全部为 0 则 `one`。例：`5::m*s^-1`、`5/2::s`、`2::one`。这是确定性显示文字，不承诺可直接当源码重新解析。

新库只提供 `unit.make` 与 `unit.format`，不先加入可能丢精度的 Float 取值接口或隐式换算。基础数组 sum/stats 仍只接受 Int，sorted 仍只接受统一 Int/String，不能将新 Quantity 直接交给这些接口。

JSON 不自动把 Quantity 压成普通数字或字符串。应用显式采用固定单位和声明过的字段格式；若用 unit.format 保存，应明确该格式仅供显示，不能假定 `unit.make` 接受该 String。无损机器编解码、复合单位解析和接口 schema 生成以后另订契约，当前不宣称已经支持。

## 3. 实现顺序和性能验证

1. P01 扫描器登记固定符号 `(machine)`、`(Machine)`、`(Quantity)`、`-->`、`--`、`<<`；已有字符串/注释模式保持各自边界。`-->` 必须比 `--`、`->` 和 `-` 优先，`<<` 比 `<` 优先；不用上下文扫描。
2. P04-06 实现定义/实例/Result 转换；P04-07 实现数量字面、不可变数值和量纲运算；两项在原 P04 验收前完成，不属于等待再选的 P10 候选。
3. P04 数量验收先用核心运算、str/io.print，不依赖尚未实现的 unit 库；P05 再注册 unit 接口、导出 machine 定义，补 JSON 拒绝与冻结规则。P06 将 [test-coverage.md](../development/test-coverage.md) 的 MACHINE/UNIT 类别变为实际 ZZY 黑盒用例。
4. P07 分别测词法、解析准备和运行：状态定义准备与发送分开，失败/成功发送分开；数量的扫描成本与有理数运算成本分开，固定记录单位表版本、分子/分母位数。

状态转移表可按 `(状态编号, 事件)` 查找，普通哈希查找目标为平均常数次表操作；事件哈希仍与字符串长度有关，不宣称整个发送绝对 O(1)。只读表可随 Program 复用，当前状态不可复用。不得每次发送重新解析箭头正文。

量纲向量固定两项，单位倍率预建；单位字面值一次准备。复杂成本主要在有理数乘除、约分和大整数，不在 `::` 的拼写。性能比较中 Python 对照也使用相同精确有理数与量纲检查，不能拿低精度 Float 运算冒充等价算法。

新增固定 `--` Token 后，紧邻的 `--x` 不再表示双重负号；若需要写 `-(-x)` 或 `- - x`。`--`/`-->` 在状态机边之外不能当减法使用；这是 v0.5 明确的词法变更。数组、字符串、注释中的箭头和单位标记仍按各自模式处理。

P04 核心行为已有实现与测试，性能收益仍待 P07 实测。
